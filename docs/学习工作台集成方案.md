# 学习工作台（Learning Workbench）集成方案

> 本文档基于对 `LearningAssistant` 项目现有代码的评估，梳理当前功能模块现状，并提出将分散的学习功能整合为统一「学习工作台」的集成方案与实施路线。

---

## 一、文档目的

1. **评估现状**：盘点现有功能模块、架构分层、数据模型与服务注册情况，识别启用 / 禁用 / 孤立的模块。
2. **集成设计**：提出「学习工作台」的总体架构、区域划分与功能映射，解决当前功能分散、入口割裂的问题。
3. **落地路线**：给出分阶段实施路径，便于后续开发推进。

---

### 2.6 现有问题与改进点

经评估，当前架构存在以下突出问题，正是「学习工作台」需要解决的核心：

1. **入口割裂、模态堆叠**：学习、统计、挑战、成就、错题、编辑器、设置全部以 `ShowDialog` 模态弹出，无法多任务并行（如边学边记笔记、边复习边查错题）。`WindowManager` 是唯一的窗口协调者，但只支持串行打开。

2. **「中心」概念重复**：存在三个类「中心」的入口 —— `MainForm`+`DashboardView`（首页）、`LearningHubForm`（学习中心，仅 2 张卡片的迷你对话框）、`LearningManagementForm`（学习管理），职责重叠，用户认知混乱。

3. **高级学习法未接入**：费曼学习、主动回忆、联想学习、渐进提示、思维激发器、学习目标、学习路径等服务与控件已完整实现，但 `LearningForm` 未调用，能力被「埋没」。

4. **侧栏导航不一致**：`MainForm` 侧栏有 4 项被注释（mentor / flashcard / notes / graph），与实际可用功能不符；闪卡复习入口隐蔽。

5. **数据模型双轨**：学习内容存在 JSON 词库（`LearningItem`）与 SQLite（`LearningItems`/`LearningItemStates`/`SpacedRepetitionItems`）两套存储，`LearningItemMigrationService` / `DataMigrationService` 已被注释停用，迁移路径中断。

6. **用户切换同步隐患**：`debug-gamification-encouragement.md` 记录的 `UserId` 不同步问题（`GamificationService.Load` vs `FlowHandler._currentUserId` vs `IUserSessionService.CurrentUserId`）仍未根除。

7. **AI 能力分散**：`AIPanelPopupService` 弹窗式 AI 面板，未与学习内容、错题、笔记深度联动；`PromptTemplateService` / `ConversationContextService` 能力未被充分使用。

## 三、学习工作台集成方案

### 3.1 设计目标

| 目标 | 说明 |
| --- | --- |
| **统一入口** | 将学习、复习、错题、笔记、目标、番茄钟整合进单一工作台窗口，取代多个模态弹窗 |
| **并行任务** | 工作台内分区域 / 分页签，支持「边学边记」「边复习边查错题」 |
| **激活沉淀功能** | 将费曼 / 主动回忆 / 联想 / 渐进提示 / 学习路径 / 学习目标等已实现但未接入的能力接入主流程 |
| **一致上下文** | 全工作台共享 `LearningContext`（用户 / 学科 / 子类别），切换学科联动所有区域 |
| **可扩展** | 以区域（Region）+ 插件式面板（Panel）组织，新增学习法只需注册面板，不改主框架 |
| **保留现有服务** | 不重写已稳定的服务层与数据层，仅重组 UI 编排与 Presenter 协作 |

### 3.2 工作台总体架构

│                LearningWorkbenchView（工作台主视图）           │
│                                                              │
│  ┌──────────────┐ ┌────────────────────────────────────────┐ │
│  │ 上下文栏     │ │ 区域 B：学习画布（Canvas）              │ │
│  │ 用户/学科/   │ │  · 学习卡（LearningCard）              │ │
│  │ 子类别/模式  │ │  · 答题 / 翻面 / 已掌握 / 待学习         │ │
│  │ 排序         │ │  · TTS / 收藏 / 笔记 速记               │ │
│  └──────────────┘ └────────────────────────────────────────┘ │
│  ┌──────────────┐ ┌────────────────────────────────────────┐ │
│  │ 区域 A：     │ │ 区域 C：学习法切换（Strategy Tabs）     │ │
│  │ 学习列表     │ │  费曼 · 主动回忆 · 联想 · 渐进提示      │ │

工作台是一个嵌入 `MainForm` 的 `UserControl`（类比现有 `DashboardView`），而非模态 `Form`。所有子区域既可独立工作，又通过共享 `WorkbenchContext` 联动。

### 3.4 关键集成点设计

#### 3.4.1 共享上下文与事件总线

工作台核心是**单一上下文、多区域联动**。现有 [EventBus.cs](file:///e:/Github/LearnTool/LearningAssistant/Common/Events/EventBus.cs) + [LearningEvents.cs](file:///e:/Github/LearnTool/LearningAssistant/Common/Events/LearningEvents.cs) 已具备基础，需补充：

```csharp
// 新增事件：工作台上下文切换
public record WorkbenchContextChangedEvent(string UserId, SubjectType Subject, SubCategoryType SubCategory, LearningModeType Mode);

// 现有可复用事件
// ItemLearnedEvent / PomodoroCompletedEvent / AchievementUnlockedEvent / GoalProgressUpdatedEvent
```

`WorkbenchContextBar` 切换学科时发布 `WorkbenchContextChangedEvent`，区域 A/B/C/D 各自订阅并刷新。**统一以 `IUserSessionService.CurrentUserId` 为唯一用户来源**，根除 2.6 节问题 6。

#### 3.4.2 Presenter 协作（不重写服务层）

工作台引入一个编排型 Presenter，**只做协调，不重复业务逻辑**：

```
LearningWorkbenchPresenter（编排）
 ├─ 复用 LearningFlowHandler（学习流程）
 ├─ 复用 LearningPresenter（学习视图逻辑）
 ├─ 复用 ContentEditorPresenter（内容编辑，改造为面板模式）
 ├─ 新增 WrongAnswerPresenter / NotePresenter / GoalPresenter（薄 Presenter）
 └─ 注入 IWindowManager（仅用于仍需独立窗口的 PDF / 浏览器）
```

`LearningFlowHandler` 已是现成的学习流程协调器（含 `MarkAsKnownAsync` 等），工作台直接调用，避免 `LearningForm` 中事件重复发布问题（见 `debug-gamification-encouragement.md` 问题 1）。

#### 3.4.3 学习法策略宿主

将费曼 / 主动回忆 / 联想 / 渐进提示统一为「学习策略」接口，由宿主按当前 `LearningItem` 动态加载：

```csharp
public interface ILearningStrategy
{
    string Key { get; }          // "feynman" / "active-recall" / ...
    string DisplayName { get; }  // "费曼学习"
    Control CreateView();        // 创建可嵌入视图
    Task ActivateAsync(LearningItem item, LearningContext ctx);
}
```

`ThinkingStimulator` 已是现成协调器，改造为实现 `ILearningStrategy` 的聚合入口即可。这样既激活了沉淀功能，又保持开放扩展。

#### 3.4.4 内容编辑器面板化

当前 [ContentEditorPresenter.cs](file:///e:/Github/LearnTool/LearningAssistant/Presenters/ContentEditorPresenter.cs) 与 `ContentEditorForm` 强耦合模态窗体。集成方案：

1. 将 `ContentEditorForm` 的编辑区抽取为 `ContentEditorPanel` UserControl，保留 `IContentEditorView` 契约。
2. `ContentEditorPresenter` 不变（已通过接口解耦），仅把 `IContentEditorView` 的实现从 Form 换成 Panel。
3. 工作台「内容管理」侧栏 Tab 承载该 Panel，支持在工作台内直接编辑当前子类别词库，无需跳转。
4. 保留 `WindowManager.OpenEditorWindow` 作为独立窗口入口（兼容旧调用）。

#### 3.4.5 数据双轨收敛

利用现有 `LearningItemStateEntity` + `SpacedRepetitionItemEntity` 作为「状态层」，JSON 词库作为「内容层」：

- **内容层**（JSON）：`LearningItem` 静态内容，由 `ContentLoaderService` 加载，`ContentEditorPresenter` 维护。
- **状态层**（SQLite）：每个用户对每个 `LearningItem` 的掌握状态、复习记录、间隔参数，由 `SqliteSpacedRepetitionService` / `LearningItemStateService` 维护。
- **关联键**：`(UserId, CategoryName, Content)` 唯一索引（已存在于 `LearningItemStates` 表）。

工作台通过 `UnifiedStudyEntryService`（已注册）统一读取「内容 + 状态」聚合视图，避免业务层直接触碰双轨存储。

### 3.6 实施路线图

按「低风险、高收益」排序，每阶段可独立交付：

#### 阶段 1：工作台骨架与上下文统一（基础）
- 新建 `LearningWorkbenchView` UserControl + `LearningWorkbenchPresenter`。
- 抽取 `WorkbenchContextBar`（用户 / 学科 / 子类别 / 模式），发布 `WorkbenchContextChangedEvent`。
- 将 `LearningForm` 的列表 + 画布 + 按钮子视图迁入工作台区域 A/B，去掉 `ShowDialog`，改为 `MainForm` 嵌入。
- 统一 `UserId` 来源为 `IUserSessionService.CurrentUserId`，修复游戏化不同步。
- 精简 `MainForm` 侧栏导航。
- **验收**：可在工作台内完成「选学科 → 学习 → 标记掌握」全流程，无模态弹窗。

#### 阶段 2：激活高级学习法
- 定义 `ILearningStrategy` 接口与 `LearningStrategyHost`。
- 将 `FeynmanLearningPanel`、`ActiveRecallForm`、`AssociationLearningForm`、`ProgressiveHintForm` 改造为策略实现（Form → UserControl 或浮层）。
- 接入 `ThinkingStimulator` 作为策略聚合器。
- 在区域 C 以 Tab 形式暴露 4 种学习法 + 闪卡复习。
- **验收**：学习任意卡片时可一键切换「费曼讲解 / 主动回忆 / 联想拓展 / 渐进提示」。

#### 阶段 3：辅助面板集成
- 区域 D 实现：错题面板（抽取 `WrongAnswerForm` 为 `WrongAnswerPanel`）、速记笔记面板（恢复 `Forms/Notes` 编译 + 新建 `QuickNotePanel`）、目标面板（复用 `GoalSettingPanel`）、番茄钟面板（复用 `PomodoroTimer`）。
- 底部状态条 `WorkbenchStatusBar` 订阅游戏化 / 番茄钟事件实时刷新。
- **验收**：学习时可并行查错题、记笔记、看目标、跑番茄钟。

#### 阶段 4：AI 助手常驻化 + 内容编辑面板化
- 将 `AIPanelPopupService` 改造为常驻侧栏 AI 面板，自动注入当前 `LearningItem` / 错题上下文到 `ConversationContextService`。
- `ContentEditorForm` 抽取为 `ContentEditorPanel`，接入工作台「内容管理」Tab，复用 `ContentEditorPresenter`。
- **验收**：工作台内可直接编辑词库、与 AI 对话答疑。

#### 阶段 5：学习路径与首页联动
- 新建 `LearningPathPanel`，对接 `LearningPathService` / `UnifiedStudyEntryService`，作为「今日计划」入口。
- `DashboardView` 增加「继续学习」按钮，一键进入工作台并定位到上次子类别（复用 `MainPresenter.View_OpenLearningWindowClicked` 的「恢复上次会话」逻辑）。
- **验收**：首页 → 工作台 → 学习路径 → 学习画布闭环。

#### 阶段 6：清理与收尾
- 移除 `LearningHubForm`（或标记废弃）。
- 恢复 / 删除侧栏被注释导航项，对齐实际可用功能。
- 评估数据迁移服务（`LearningItemMigrationService` / `DataMigrationService`）是否重启，或明确废弃。
- 文档同步：更新本方案，记录实际落地区域。
