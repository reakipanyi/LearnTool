## 一、重新认识产品本质 — "范围蔓延"是症状不是病

### 1.1 起源:一个聚焦的真实痛点

> "本来是想做 TTS 和 OCR 阅读英文文档的"

这是**非常好的起点** — 一个真实的、自己的、高频的痛点。家长读英文文档/PDF,TTS 帮忙读出来,OCR 把扫描件转文字。这个核心价值是**经过个人验证的**,比绝大多数"我猜用户需要"的产品强 10 倍。

### 1.2 蔓延路径(从代码反推)

```
TTS + OCR 英文文档阅读(起源,真实痛点)
   │
   ├─ 加 PDF 阅读、高亮、书签(合理延伸,阅读体验)
   ├─ 加间隔重复卡片(合理,读完要记)
   ├─ 加 AI 问答/导师/费曼(合理,AI 火了顺手加)
   ├─ 加番茄钟、目标、提醒(合理,辅助学习习惯)
   │
   ├─ 加错题本、笔记、收藏(合理延伸)
   ├─ 加知识图谱(可能为了可视化)
   ├─ 加游戏化(为了孩子?)
   ├─ 加 5 款 WebView2 游戏(为了孩子)
   ├─ 加内置浏览器、网页摘录(顺手)
   ├─ 加百度网盘 AI 分析(实验性?)
   ├─ 加百度网盘备份(数据安全)
   ├─ 加本地备份多 Provider(数据安全,可能过度)
   ├─ 加测验/语音回忆(做了未注册 — 没真用)
   └─ 加统计/图表/报告(想做但没做完 — W-004~W-010)
```

### 1.3 关键认知:范围蔓延不是"错误",是"没有用户分层的自然结果"

你和孩子是**两类完全不同的用户**:

| 维度 | 家长(你) | 孩子 |
| --- | --- | --- |
| 核心场景 | 读英文文档/PDF、记忆专业词汇 | 学英语单词、玩中记忆 |
| 偏好功能 | TTS / OCR / PDF / AI 导师 / 错题本 | 卡片学习 / 游戏化 / 趣味游戏 / 徽章 |
| 容忍复杂度 | 高(愿意配置) | 低(要点了就玩) |
| 视觉风格 | 专业、信息密度 | 童趣、大按钮、即时反馈 |
| AI 用途 | 解释专业概念、翻译 | 把单词讲成故事、造例句 |

**所有功能加在一起不混乱,是因为两类用户的需求混在了一个 UI 里**。这才是真正要解决的问题。

## 二、家庭场景下的产品策略 — "双用户分层"而非"砍功能"

### 2.1 核心策略:不是砍功能,是分层呈现

之前文档建议"砍掉游戏、剥离网盘分析" — 这在家庭场景下是**错的**。正确做法是:

```
应用启动
   │
   ├─ 选择用户(已有 R-017 多用户)
   │     │
   │     ├─ 家长模式 → 默认进入"文档阅读工作台"
   │     │     核心入口:PDF 阅读 / TTS / OCR / AI 导师 / 错题本
   │     │     隐藏:5 款游戏、童趣元素
   │     │
   │     └─ 孩子模式 → 默认进入"趣味学习中心"
   │           核心入口:卡片学习 / 游戏 / 徽章 / 番茄钟
   │           隐藏:PDF / OCR / 网盘 / 浏览器 / 复杂统计
   │
   └─ 顶部一个"切换用户"按钮(已有 UserSwitcherControl)
```

> 这其实就是 W-001/W-002 的"用户切换不灵活"问题的**真正解法** — 不是为了"专业感",而是为了**让两类用户看到不同的产品**。

### 2.2 现有架构的天然契合

好消息:你已有的多用户、UserSwitcherControl、SubjectTemplates 已经为这个分层做好了准备。需要做的是:

1. **用户配置加 `UserRole` 字段**(Parent / Child / Custom)
2. **侧边栏导航项按角色过滤**(已有 `NavigationItem`,加 `VisibleRoles` 属性)
3. **首页 Dashboard 按角色渲染不同布局**

> 这是**小到中等代码量**,但产品价值巨大的改造。

### 2.3 家长模式 — 回归起源,聚焦"读 + 听 + 记"

家长模式应该把**起源功能(TTS + OCR + PDF)** 拉回 C 位:

| 功能 | 当前状态 | 家长模式定位 |
| --- | --- | --- |
| PDF 阅读 + 高亮 + 书签 | ✅ 完整 | **核心入口 1** |
| TTS(KokoroSharp 本地 + Qwen 云) | ✅ 完整 | **核心入口 2**(读英文文档刚需) |
| OCR(Tesseract) | ✅ 完整 | **核心入口 3**(扫描件/图片英文) |
| 翻译(百度翻译) | ✅ 完整 | 配合 PDF 选词翻译 |
| 卡片学习 + FSRS | ✅ 完整 | 读完文档后提取词汇入卡片 |
| AI 导师 | ✅ 完整 | 解释难句、翻译专业概念 |
| 错题本 | ✅ 完整 | 家长不太需要,可隐藏 |
| 番茄钟 | ✅ 完整 | 可选 |
| 5 款 WebView2 游戏 | ✅ 完整 | **隐藏**(家长不需要) |
| 百度网盘 AI 分析 | ✅ 完整 | **隐藏**(除非家长真在用) |
| 内置浏览器 | ✅ 完整 | **隐藏**(用系统浏览器即可) |
| 知识图谱 | ✅ 完整 | 可选,二级菜单 |

**家长模式首页**:就是 PDF 阅读器 + TTS 控制条 + 词汇提取按钮。**回归起源**。

### 2.4 孩子模式 — 聚焦"玩 + 记 + 反馈"

| 功能 | 当前状态 | 孩子模式定位 |
| --- | --- | --- |
| 卡片学习(多学科) | ✅ 完整 | **核心入口 1** |
| 5 款 WebView2 游戏 | ✅ 完整 | **核心入口 2**(消消乐/翻牌/连连看/打地鼠/拼写) |
| 游戏化(等级/XP/徽章/成就) | ✅ 完整 | **核心反馈层** |
| 番茄钟(短时专注) | ✅ 完整 | 配套,15 分钟一段 |
| 每日挑战 | ✅ 完整 | 制造每天回来的理由 |
| TTS 朗读单词 | ✅ 完整 | 单词发音 |
| AI 讲故事解释单词 | ✅ 完整 | 把抽象词讲成故事 |
| PDF 阅读 | ✅ 完整 | **隐藏**(孩子不需要) |
| OCR | ✅ 完整 | **隐藏** |
| 网盘 / 浏览器 / 统计中心 | ✅ 完整 | **全部隐藏** |

**孩子模式首页**:大按钮卡片 + 今日游戏入口 + 徽章墙。**像 Duolingo 不像 Anki**。

## 三、家庭场景下的优先级 — 完全重排

### 3.1 之前文档的优先级(已作废)

P0 数据底座 / P1 收敛 UI / P2 增值能力 — 这是"面向大众"的节奏。

### 3.2 家庭场景的真实优先级

| 优先级 | 动作 | 代码量 | 价值 |
| --- | --- | --- | --- |
| **P0-A** | 用户角色字段 + 侧边栏按角色过滤 | 小 | 立刻让"自己用"和"孩子用"分开 |
| **P0-B** | 家长模式首页改造为 PDF + TTS 起源界面 | 中 | 回归产品本源,自己用得爽 |
| **P0-C** | 孩子模式首页改造为大按钮 + 游戏 | 中 | 孩子愿意用 |
| **P0-D** | 删 Dashboard 假数据,做角色化空状态 | 小(技术侧 O-002 已规划) | 不再误导 |
| **P1-A** | TTS 阅读英文 PDF 的体验打磨(连续朗读、断点续读、语速记忆) | 中 | **起源功能价值最大化** |
| **P1-B** | PDF 高亮 → 一键入卡片(已有 HighlightSyncService) | 小 | 读 + 记打通 |
| **P1-C** | 孩子模式游戏数据回写到学习统计 | 小 | 看到孩子的进步 |
| **P1-D** | 多用户切换 UI 改造(头像 + 浮层,W-001/W-002 已规划) | 中 | 自己和孩子切换丝滑 |
| **P2** | 统计/图表/报告(已有方案) | 大 | 重要但不紧急,孩子用不上,家长偶尔看 |
| **P3** | 面向大众的优化(Store/官网/商业化/telemetry) | — | **暂不做**,等"家庭自用打磨好"再考虑 |

### 3.3 关键洞察 — "起源功能"被低估了

代码里 TTS / OCR / PDF 已经做得很完整(`Services/TTS/`、`Services/Pdf/`),但**首页没有把它们放在 C 位** — 首页是 `DashboardView` + `StatCard`,展示的是统计假数据。

**这就是范围蔓延的最大代价**:你最好的功能(TTS+OCR+PDF 阅读英文)被埋在了次要入口,反而是后加的统计/游戏/网盘抢了首页。

> **一句话总结改进方向:把起源功能拉回家长模式首页,把游戏拉回孩子模式首页,其他全部退到二级菜单。**

## 四、家庭场景下的"北极星" — 不需要对外汇报,但需要自我检验

### 4.1 不需要复杂指标体系

之前文档的"四级 KPI 体系"是面向大众的。家庭自用只需要回答一个问题:

> **"这周我和孩子用了几次?用得爽吗?"**

### 4.2 家庭版北极星(简化版)

| 角色 | 北极星 | 衡量方式 |
| --- | --- | --- |
| 家长 | 每周用 TTS/OCR 读了几篇英文文档 | 本地计数,设置页可见 |
| 孩子 | 每周完成了几张卡片 / 玩了几局游戏 | 本地计数,首页徽章墙可见 |
| 整体 | 连续使用天数(打卡) | 首页"已坚持 N 天" |

### 4.3 落地建议

- 设置页加一个"家庭学习看板"Tab,**只对自己可见**,不上传。
- 字段简单:`weekly_parent_sessions`、`weekly_child_cards`、`streak_days`。
- **不需要 telemetry 服务、不需要 NPS、不需要访谈** — 你和孩子就是用户,直接问。

## 五、面向大众?— "先打磨好家庭版,大众版自然浮现"

### 5.1 不要现在决定是否面向大众

你说"还没想好怎么改进面向大众" — **这是对的**。在家庭自用阶段就考虑大众化,会导致:

- 为了"通用"牺牲"特化",自己用得不爽
- 增加引导、合规、telemetry、商店上架等大量非核心工作
- 模糊产品定位,加剧范围蔓延

### 5.2 正确路径:家庭版打磨 6 个月,再评估

```
现在 ──── 6 个月 ──── 决策点
   │                        │
   家庭自用打磨               评估:
   - 双用户分层落地            ① 自己还在高频用吗?
   - 起源功能回归首页          ② 孩子持续在用吗?
   - 砍掉家庭不用的功能        ③ 有没有自然传播?
                            ④ 有没有人主动问"能不能给我用"?
                                │
                                ├─ 是 → 启动大众化(参考原《产品经理改进意见.md》)
                                └─ 否 → 继续家庭自用,开源即可
```

### 5.3 "自然传播信号"是判断大众化时机的最佳指标

不需要做市场调研,看这几个信号:

- 朋友看到你在用,问"这是什么?能给我装一个吗?" → **强信号**
- 在 GitHub 收到 issue "能不能加 XX 功能(说明真有人在用)" → **中信号**
- 在群里/社区有人讨论你的工具 → **强信号**
- 自己用了 3 个月后还在用 → **基础信号**(如果自己都不用了,别想大众)

### 5.4 如果决定大众化,先做最小验证

不要直接 Microsoft Store 上架,先:

1. **写一篇"我为什么做这个工具"的博客/小红书** — 讲起源(TTS+OCR 读英文)、讲孩子用、讲范围蔓延的真实故事。**真实故事比功能列表有吸引力 10 倍**。
2. **GitHub README 重写** — 当前 README 应该是技术向的,改成"家长 + 孩子"场景故事。
3. **建一个微信群/Discord** — 装了的人进群,直接聊。
4. **观察 1 个月** — 有 50 个真实用户 + 10 个活跃,再考虑 Store 上架。

## 七、TL;DR — 给"自己和孩子用"的 3 个最小动作

如果只做 3 件事,按这个顺序:

1. **加 `UserRole`(Parent/Child)字段,侧边栏按角色过滤** — 一周内,小代码量。立刻让"自己用"和"孩子用"看到两个不同的产品。
