# 打地鼠 设计方案

> 项目：LearningAssistant（WinForms + WebView2）
> 目标：在现有"单词消消乐""记忆翻牌"基础上，新增一款 **"打地鼠"（Whack-a-Mole）** 游戏：地鼠洞中弹出单词/释义，玩家在**限时**里点中正确配对，锻炼"反应 + 配对"的快速识别。
> 本文档只做方案设计，不涉及代码实现。

---

## 1. 背景与目标

现有游戏要么无时间压力（消消乐/连连看），要么是节奏自控的翻牌。缺少一款**有实时时间压力、快节奏**的玩法，用于高密度的应急复习。

本方案设计 **"打地鼠"**：
- 复用已验证的 WebView2 + 内容编辑器数据 + 成绩回写路径（`WebView2GameFormBase` + `WordMatchGameService`）；
- 玩法核心差异：**限时 + 随机冒出目标**，点中正确配对得分，点错/漏点计失误；
- 纯静态网页（HTML + CSS + JS），鼠标 + 触屏可点。

---

## 2. 玩法设计

### 2.1 核心规则（打地鼠）
- 盘面上布置 **M×N 个"地鼠洞"**（如 3×3 或 3×4）。
- 每轮从抽中的词条中选出一个**目标词条**，在目标洞显示"单词"（或释义），同时在若干干扰洞显示**其他词条的释义**（或单词）。
- 玩家需**快速点击与目标配对的那张干扰卡**：
  - **点中正确配对** → 得分 + 连击 + 本词条记答对；
  - **点错** → 失误 +1，记该词条答错，进入下一题；
  - **超时未点** → 目标消失，漏题记 0，进入下一题。
- 限时（如 60s）结束 → 结算。

### 2.2 出题与难度
- 目标呈现形式（可切换/随机）：
  1. **目标=释义，找单词**：目标洞显示释义，干扰洞显示多个单词，点正确单词；
  2. **目标=单词，找释义**：目标洞显示单词，干扰洞显示多个释义，点正确释义。
- 抽词：复用 `BuildItems(context, N, selection)`，默认 `WrongFirst`。干扰项从同库其他词条中随机抽取。
- 干扰项数：3–5 个（即干扰洞数量）。
- 难度：
  - **简单**：目标滞留 3s，干扰少，不限失误；
  - **普通**：目标滞留 2s，干扰 4 个，限时 60s；
  - **困难**：目标滞留 1.5s，干扰 5 个，限时 60s，失误 5 次提前结束。

### 2.3 计分与反馈
- 计分：点对基础分 × 连击系数；点错/超时不加分。
- **连击**：连续点对递增；点错/超时清零。
- 反馈：
  - 点对：绿圈炸裂 + 音效 + 得分飘字；
  - 点错：红圈抖动 + 提示；
  - 超时：目标"漏跑"动画。
- 发音：目标洞单词可 `speechSynthesis` 朗读（可选自动播放）。

### 2.4 通关与结算
- 结算页：得分、正确数/总题、正确率、失误数、最高连击、用时、星级。
- "再来一局"（同组重排）/"换一组"（重新抽词，`restart`）。

## 3. 数据接入方案

### 3.1 复用现有服务
- **取词**：`WordMatchGameService.BuildItems(context, N, selection)`，返回 `List<WordMatchItemDto>`（含 `Id / Word / Meaning`）。目标洞与干扰洞皆来自该批词条。
- **成绩回写**：`WordMatchGameService.ApplyResults(userId, context, results)`，答错/超时的进错题本。
- **宿主**：新增 `WhackAMoleGameForm`，继承 `WebView2GameFormBase`。

### 3.2 成绩回写语义
- 每个被抽中并**出过题**的词条记为一条结果：玩家点中正确配对 → `Correct = true`；点错/超时 → `Correct = false`。
- 未出题的词条不进入 results；前端结算时统一 `gameEnd` 上报。

### 3.3 宿主窗体
新增 `WhackAMoleGameForm`，与记忆翻牌一致，仅：
- `FormTitle` → "🔨 打地鼠"；
- `HtmlFileRelativePath` → `Resources/WhackAMoleGame/index.html`；
- `BuildData` → `BuildItems(context, 12, WordSelection.Random)`（干扰项多，取更多词备用）。

## 4. 前端页面设计（静态 HTML）

### 4.1 文件组织
```
Resources/WhackAMoleGame/
  index.html     # 页面骨架（地鼠洞 + 目标卡）
  style.css      # 洞、地鼠/卡片动画、hit/miss 反馈、主题
  game.js        # 出题轮询、命中判定、计时计分、结算、通信
```
- 纯原生 JS，无外部依赖，离线可用；支持 `?mock=1`。

### 4.2 页面布局
- 顶部：标题、得分、连击、正确数/题数、倒计时（环形或数字）。
- 中部：**地鼠洞盘面**（CSS `grid`，如 3×4）。目标洞高亮边框，干扰洞随机冒出卡片。
- 底部：策略提示条（"点中与目标配对的那张卡"）、发音按钮（重播目标）。

### 4.3 地鼠洞与动画
- 每个洞含一张可翻转/弹出的卡：默认隐藏（洞），出现时上浮。
- 目标洞与干扰洞**仅靠内容区分**（目标洞可加深边框/阴影），以保持公平。
- 反馈动画：`hit`（绿圈）/ `miss`（红抖）/ `escape`（目标上移消失），全部 CSS transform，避免频繁重排。
- 明暗主题：`body[data-theme]` 联动。

### 4.4 出题循环
- 定时器驱动：每轮（滞留时长）重出题；用 `setTimeout` 链控制出题节奏，避免多 timer 竞争。
- 点按期间锁定其他洞（同一轮只判一次），避免连点刷分。
- 目标词条在本轮内**不重复**作为干扰项同义混淆（同一词条的单词与释义不互作目标/干扰）。

## 8. 技术要点与风险

1. **出题节奏**：用 `setTimeout` 链，避免多 timer 竞争与累积误差；超时走同一判定函数。
2. **单轮锁定**：点名后锁定该轮其余洞，防止连点刷分；下一轮解除。
3. **干扰项防混淆**：同一词条的单词/释义不互为目标/干扰，避免自相矛盾。
4. **动画性能**：全部 CSS transform/opacity，避免 layout 抖动；命中/漏次用类切换。
5. **动画 fill 覆盖（前期踩过）**：确认弹出/命中动画不覆盖洞的显示/隐藏终态，必要时 `animation: none !important`。
6. **成绩回写去重**：按出现过的词条 id 上报一次，判定用局内 key，`id` 仅回写用。
7. **中文 JSON 编码**：UTF-8。
8. **词库不足**：干扰项不足时提示并降低干扰数/N。
9. **发音**：`speechSynthesis` 静默降级。
10. **主题一致**：`data-theme` 联动。

## 11. 已采纳优化

### 打地鼠专有
1. **错误加权插队**：点错或漏掉的词条**插队更频繁地出现**，命中后降低权重——让快节奏游戏也服务"薄弱词闭环"。
2. **实时难度自适应**：连续命中→缩短目标滞留 / 增加干扰项数；连续失误→放宽滞留，避免挫败或无聊。
3. **漏点单独统计**：把"点错"与"超时漏点"分开统计与惩罚——两者语义不同（点错=当轮主动选错，漏点=没反应过来）。
4. **开局预告**：正式倒计时前给 2s 空场让玩家定位手感，防止"还没看清就开始"。
5. **防刷分加固**：在单轮锁定基础上，再禁止"同一洞被连续点中两次计分"，防点住不放刷分。

### 三款共用
6. **抽前端公共件 `Resources/Shared`**：把消消乐/翻牌/打地鼠重复的 `bridge()/sendToHost/toast/esc()`、发音、粒子反馈、主题变量、`{type,payload}` 消息协议、camelCase 封装统一抽取共享，各游戏只写差异。**当前代码库收益最高的一步**。
7. **统一难度/配置入口**：基类定义共识结构（如 `{difficulty, limit, hintBudget}`）由 `init` 下发，各前端复用，避免各自造难度轮子。
8. **通用成绩上报模板**：统一"每词条一条结果 + `correct` 布尔 + 局内 key 判定"协议，本款命中判定则复用同一 DTO。
