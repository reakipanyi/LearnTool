# PDF 翻译「自动高亮」完整方案

> 状态：已确认方案，按「当前页 → 整本文本层 → 整本扫描件」分步实现
> 适用范围：PDF 阅读器 · 翻译侧栏 · 自动框选文字区域

## 1. 需求确认

| 编号 | 确认项 | 结论 |
| --- | --- | --- |
| 1 | 作用范围 | 既要当前页（双页模式处理两页），也要「整本自动框选」 |
| 2 | 框选后行为 | 默认**只框选**，点击某个框才翻译；不自动翻译全部段落 |
| 3 | 再次点击按钮 | 默认**清除本页自动高亮**，不是重新生成 |
| 4 | 扫描版支持 | 当前页扫描件首版支持（OCR 行框）；整本扫描件放到第 3 步 |

补充约束：

- 自动框选必须**排除页码**，并尽量排除页眉/页脚等非正文内容。
- 自动高亮与手动高亮共存，但自动高亮需要可识别、可批量清除。
- 自动高亮不改变现有手动高亮、标注、撤销、导出行为。
- 点击自动框只翻译该框，译文复用现有顶部译条与翻译面板。

## 2. 交互设计

### 2.1 翻译侧栏按钮

在「翻译」面板操作区新增第四个按钮：

```text
[🔍 整页识别] [✂ 句子跟读] [➕ 加入本页译文] [🖍 自动高亮]
```

行为：

1. 当前页/双页存在自动高亮 → 清除本页（双页两页）自动高亮与版面缓存。
2. 当前页/双页不存在自动高亮 → 生成版面块并落库，显示浅色虚线框。
3. 自动框默认不发起翻译请求。
4. 点击某个自动框 → 走现有选区翻译链路：
   - 命中本页译文缓存则直接回显；
   - 未命中才调用翻译服务；
   - 结果写回高亮实体与顶部译条。

### 2.2 整本入口

通过「自动高亮」按钮的右键菜单提供：

- `整本自动框选（文本层）`：只处理有文本层的页，扫描页跳过。
- `整本自动框选（含扫描页 OCR）`：无文本层的页走 OCR 行框（第 3 步）。
- `清除整本自动高亮`：删除本文档所有自动高亮并清理版面缓存。

整本任务在后台执行，显示进度；可取消；已完成页按页落盘，支持断点续跑。

### 2.3 懒加载策略

- 整本任务只生成**按页版面缓存**，不一次性写入几千条高亮。
- 用户浏览到某页时，如果整本自动高亮处于开启状态，且该页有版面缓存、尚无自动高亮，则把该页版面块转成高亮落库。
- 当前页手动清除后，该页加入「已抑制页」集合，避免翻页回来又被自动生成；再次点击按钮可单页恢复。

## 3. 技术方案

### 3.1 文本行提取（文本层）

新增 `IPdfService.GetTextLines(int pageIndex)`，`PdfiumPdfService` 实现：

1. `GetPdfText(pageIndex)` 取得整页文本（保留 `\r\n`）。
2. 按原始字符串偏移逐行切分，避免规范化换行导致偏移错位。
3. 每一行调用 `GetTextBounds(new PdfTextSpan(pageIndex, start, length))` 取得词级矩形。
4. 合并该行所有矩形为行包围盒。

坐标换算（PDF 点 → 页面归一化 0~1，左上原点）：

```text
x = left / pageWidth
y = (pageHeight - top) / pageHeight
w = (right - left) / pageWidth
h = (top - bottom) / pageHeight
```

注意：PdfiumViewer 返回的 `PdfRectangle` 以左下为原点、`Top > Bottom`、`Height` 可能为负，合并时必须用 `Min/Max` 取真实上下边界。

### 3.2 OCR 行框（扫描页）

- `IOcrService` / `IPdfOcrService` 新增行框版识别：

```csharp
Task<OcrLayoutResult?> RecognizeLayoutAsync(byte[] image);
Task<OcrLayoutResult?> RecognizeLayoutWithAutoLanguageAsync(byte[] image);
```

- Tesseract 使用 `PageIteratorLevel.TextLine` 遍历：

```csharp
using var iter = page.GetIterator();
iter.Begin();
do
{
    if (iter.TryGetBoundingBox(PageIteratorLevel.TextLine, out var rect))
    {
        var text = iter.GetText(PageIteratorLevel.TextLine);
        // rect.X1 / Y1 / Width / Height
    }
}
while (iter.Next(PageIteratorLevel.TextLine));
```

- 行框以图像像素返回，再归一化为页面 0~1 坐标。
- 识别语言沿用现有自动语言检测逻辑。
- 文本索引与自动高亮共用 OCR 结果缓存，避免整本扫描件 OCR 两遍。

### 3.3 文本行 → 段落块

新增 `PdfTextBlockBuilder`（Core，纯逻辑、可单测）：

1. 清洗空白、丢弃空行与越界行。
2. 计算行高中位数，作为字号/边距基准。
3. 页码过滤（组合条件，避免误删正文数字）：
   - 文本匹配页码正则，且位于页边带（顶部 10% / 底部 10%）→ 删除；
   - 页边窄带（顶部 6% / 底部 6%）内字号明显小于正文（< 0.65 × 中位行高）→ 删除；
   - 正文带内的纯数字行保留。
4. 行合并为视觉行：
   - 相邻行垂直重叠率 > 50%，且水平间距 < 2 倍行高 → 合并；
   - 双栏之间的大间距不合并。
5. 视觉行合并为段落块：
   - 垂直间距 < 0.8 倍行高；
   - 左边缘对齐（差值 < 0.05）或中心对齐；
   - 上一行不以 `。！？.!?` 等句末符号结束；
   - 下一行不是列表标记、不是字号突变的标题；
   - 行发生向上跳变或跨栏 → 断块；
   - 中文直接拼接，拉丁文补空格；行尾连字符断词修复。
6. 块矩形做少量外扩并裁剪到 `[0,1]`。
7. 丢弃无字母/数字的块。

输出模型：

```csharp
PdfAutoTextBlock { Text, X, Y, Width, Height, LineCount, FontSize }
PdfAutoLayoutPage { PageIndex, Source, Blocks, CreatedAtUtc }
```

### 3.4 自动高亮落库

`PdfHighlight` 新增：

```csharp
bool IsAutoGenerated
string? AutoGroupId
string? TranslationLanguage
```

- `AutoGroupId` 由 `文档路径 + 页码 + 版面版本` 哈希得到，保证同一页重复生成可覆盖、可精准清除。
- `IHighlightService` 新增批量接口：

```csharp
Task<IReadOnlyList<PdfHighlight>> AddHighlightsAsync(string pdfPath, IReadOnlyList<PdfHighlight> highlights);
List<PdfHighlight> RemoveAutoHighlightsForPage(string pdfPath, int pageIndex, string? autoGroupId = null);
List<PdfHighlight> RemoveAllAutoHighlights(string pdfPath);
```

- 批量添加只计算一次文件哈希、只写一次磁盘，避免逐条保存造成卡顿。
- 自动高亮使用蓝色系：极淡填充 + 虚线边框，与手动荧光笔区分。

### 3.5 版面缓存

- 目录：`AppPaths.PdfAutoLayoutDir`（`{用户目录}/pdf_auto_layout`）。
- 文件名：`{文档路径哈希}_{文档指纹}_p{页码}.json`，一页一文件，支持断点续跑、避免多窗口互相覆盖。
- 文档状态文件：`..._state.json`，记录：

```csharp
bool WholeBookEnabled
HashSet<int> SuppressedPages
DateTime UpdatedAtUtc
```

- 文档指纹变化（文件被替换）时缓存自动失效。

### 3.6 翻译与缓存

- 点击自动框优先使用高亮实体上的 `TranslationText`。
- 其次使用现有 `PdfSelectionTranslationCache`（按文档/页码/文本哈希）。
- 未命中才请求翻译服务。
- 自动高亮默认不触发批量翻译，避免一次性产生大量 API 费用。
- 已知问题：`BaiduTranslationService` 现有 Unicode 清洗会删除重音字母与非中英文字符，后续单独修复，不影响本方案首版。

## 4. 分步实现与验收

### Step 1：当前页自动高亮

范围：

- 文本层行提取 + 段落分块 + 页码过滤；
- 扫描页 OCR 行框；
- 当前页 / 双页生成、清除；
- 点击自动框翻译；
- 自动高亮持久化与绘制样式；
- 翻译侧栏按钮；
- 单元测试与构建验证。

验收：

1. 打开文本层 PDF，点击「🖍 自动高亮」，当前页正文出现浅蓝虚线框，页码不被框选。
2. 双页模式两页都生成。
3. 点击某个框，顶部译条显示该框译文；再次点击同一框不重复请求。
4. 再次点击按钮，本页自动高亮全部清除。
5. 扫描页点击按钮，能基于 OCR 行框生成框选；OCR 不可用时给出明确提示。
6. 手动高亮、标注、撤销、导出不受影响。
7. 全量构建与相关单元测试通过。

### Step 2：整本文本层自动框选

范围：

- `PdfAutoLayoutService` 按页构建与磁盘缓存；
- 右键菜单「整本自动框选（文本层）」；
- 后台任务、进度、取消；
- 页面显示时懒加载当前页高亮；
- 「清除整本自动高亮」。

验收：

1. 整本任务只写版面缓存，不一次性写入全部高亮。
2. 任务完成后逐页浏览，首次进入某页自动出现框选。
3. 中途取消后再次执行，已完成页命中缓存不重复提取。
4. 当前页清除后翻走再回来不会自动恢复。
5. 清除整本后所有自动高亮与版面缓存被移除。

### Step 3：整本扫描件自动框选

范围：

- 复用 OCR 行框管线；
- 右键菜单「整本自动框选（含扫描页 OCR）」；
- 进度、取消、断点续跑；
- 扫描页 OCR 结果缓存复用，避免重复识别。

验收：

1. 纯扫描 PDF 可整本生成框选。
2. 已完成页二次执行不重复 OCR。
3. 取消后保留已完成页缓存。
4. OCR 失败页不阻断整本任务，并在结果中标记跳过页。

## 5. 数据与性能

| 项目 | 策略 |
| --- | --- |
| 文本层单页提取 | 一次 `GetPdfText` + 每行一次 `GetTextBounds`，通常几十行 |
| OCR 单页 | 固定宽度 1600px 渲染，按行框返回 |
| 高亮落库 | 批量一次写盘 |
| 整本 | 一页一缓存文件，懒加载生成高亮 |
| 取消 | `CancellationToken` 每页检查 |
| 重复执行 | 命中页缓存直接复用 |

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 双栏/表格误合并 | 水平间距阈值 + 左边缘/中心对齐 + 向上跳变断块 |
| 正文纯数字被误删 | 仅在页边带删除页码；正文带保留 |
| OCR 行框偏移 | 使用 Tesseract 原始页坐标，归一化后与页面同坐标系 |
| 整本高亮过多 | 只缓存版面，按页懒加载 |
| 翻译费用失控 | 默认只框选，点击才翻译 |
| 多窗口写冲突 | 一页一文件 + 文档状态独立文件 |
| PDF 文件被替换 | 文档指纹变化自动失效缓存 |
