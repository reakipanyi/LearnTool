# LearningAssistant 需求分析文档

> **文档说明**：对需求挖掘结果进行过滤、冲突识别、边界场景分析和约束汇总（已对照 2026-08 最新代码补全细化）。

## 一、需求有效性过滤

| 需求编号 | 需求描述 | 有效性判断 | 理由 |
|---------|---------|-----------|------|
| R-001 ~ R-020 | 已识别的 20 项基础显性需求 | ✅ 全部有效 | 代码中均有对应实现，为产品核心功能 |
| R-021 ~ R-031 | 新增 11 项显性需求 | ✅ 有效 | 均有代码支撑（R-030 测验/语音回忆代码存在但当前未注册，标注为"待启用"） |
| I-001 ~ I-013 | 已识别的 13 项隐性需求 | ✅ 全部有效 | 均有代码支撑，是系统必要能力 |
| - | **多用户社交功能**（好友、排行榜） | ❌ 过滤 | 当前代码中只有本地多用户切换，无社交属性 |
| - | **在线课程/视频播放** | ❌ 过滤 | 产品定位为知识记忆辅助工具，非课程平台 |
| - | **实时多人协作学习** | ❌ 过滤 | 桌面单机应用，无协作基础设施 |

## 三、边界场景识别

| 场景编号 | 边界场景描述 | 影响模块 | 风险等级 | 当前处理状态 |
|---------|-------------|---------|---------|-------------|
| B-001 | 学习项数量巨大（>10万条）时的加载性能 | 学习引擎 / 数据层 | 🔴 高 | 部分缓存，未做分页/虚拟列表 |
| B-002 | 离线状态下 AI / 云同步 / 在线 TTS 不可用 | AI服务 / 云存储 / TTS | 🟠 中高 | 本地 KokoroSharp TTS 可降级；AI 有 `FallbackAIService` 多厂商回退 |
| B-003 | 多用户数据隔离与切换 | 用户系统 | 🟡 中 | 有 UserId 字段，但 UI 切换为下拉框不灵活（W-001），顶部新增按钮重复（W-002） |
| B-004 | 学习过程中程序崩溃/意外退出 | 崩溃恢复 | 🟡 中 | 有 CrashRecoveryService，恢复粒度待验证 |
| B-005 | PDF 超大文件（>500MB）渲染性能 | PDF 模块 | 🟡 中 | 依赖 Pdfium，未做懒加载优化 |
| B-006 | 并发写入冲突（多实例同时运行） | 数据持久化 | 🟠 中高 | 有基础字段，但未做文件锁/单实例限制 |
| B-007 | 极低配置机器运行本地 AI/TTS | AI / TTS | 🟡 中 | KokoroSharp 支持 CPU 模式，但性能无保障 |
| B-008 | 数据迁移过程中断电/崩溃 | 数据迁移 | 🔴 高 | 已有 `MigrationCheckpointEntity` 断点续传设计，但迁移服务当前被注释停用 |
| B-009 | 学习时长统计为空（`TimeSpentMinutes` 无赋值点） | 数据分析 | 🔴 高 | 时长恒为 0，报告失真（W-005），需补时长写入 |
| B-010 | 新用户无学习数据时统计展示 | 数据分析 | 🟡 中 | Dashboard StatCard 写死初始假值（W-010），需空状态引导 |

| **兼容性约束** | 数据格式 | 需兼容旧版 JSON 格式数据 | 数据迁移 |

## 五、分析与结论（衔接《优化改进方案.md》）

### 5.1 核心矛盾

1. **数据权威源未统一**：学习统计数据分散在 JSON（`LearningAnalyticsService`）与多个 DB 实体（`StudyStats`/`ReviewLogs`/`WrongAnswer`/`PomodoroRecord`/`UserProfile`），口径不一 → 需引入**统一统计聚合服务**。
2. **统计 UI 与入口碎片化**：三套统计界面 + 统计入口失效 + 首页假数据 → 需**收敛为单一学习数据中心并打通入口**。
3. **用户管理入口重复且切换不灵活**：下拉切换 + 顶部 ➕ 与设置重复 → 需**改造首页用户切换并清理死代码**。

### 5.2 后续处理路径

- 详细方案见仓库根 `优化改进方案.md`，并按模块拆分为 `docs/优化改进方案/` 下的模块级方案文档。
- 优先级：P0（数据底座：时长写入/聚合服务/JSON迁移/首页真实数据）→ P1（收敛 UI、统一图表、恢复入口）→ P2（报告升级、增值能力、用户切换改版）。
