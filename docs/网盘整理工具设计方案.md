## 一、方案概述

### 1.1 背景与目标

现有 BaiduPanAnalysisForm 已实现：
- AI 分析网盘目录结构，生成整理建议（删除 / 移动 / 重命名 / 合并文件夹）
- 批量勾选建议后一键执行（通过 PanExecutionEngine 调用百度 filemanager API）

**痛点**：AI 建议覆盖范围有限，大量个性化整理需求需要人工交互完成（类似资源管理器的手动整理）。

**设计目标**：新增独立窗体 PanOrganizerForm（网盘整理工具），提供类资源管理器的双栏目录树 + 文件列表交互，支持：
- AI 建议一键载入为"待办操作"，在整理工具中可视化预览并逐条确认
- 双目录树左右独立浏览，支持跨目录拖拽移动文件
- 键盘快捷键：F2 重命名、Delete 删除、Ctrl+Shift+N 新建文件夹、Ctrl+Z 撤销最近操作
- 右键菜单：复制、剪切、粘贴、重命名、删除、打开所在位置

## 三、交互流程设计

### 3.1 从 AI 分析窗口打开整理工具

`
用户在 BaiduPanAnalysisForm：
  1. 完成 AI 分析，获取 recommendations 列表
  2. 点击 [🧰 打开整理工具] 按钮（新增）
     └─> 构造参数：snapshot, 选中的 recommendations, 根目录路径
  3. new PanOrganizerForm(...) → Show(this)

PanOrganizerForm 初始化：
  1. 左栏：展示快照根目录
  2. 右栏：展示快照根目录（默认相同，用户可切换）
  3. 底部"待办操作"Tab：将传入的 recommendations 逐条转为待办项，默认全部勾选
  4. 用户可勾选/取消、双击编辑目标路径、移除/跳过/立即执行
`

### 3.2 拖拽移动流程

`
用户操作：
  1. 在左栏 ListView 中选中 1~N 个文件/文件夹
  2. 按住左键拖到右栏 TreeView 目标节点
     • 光标显示 📦 + 拖动项数量
     • 目标 TreeNode 背景高亮
     • 目标不可用（源=目标/子目录）时显示 🚫
  3. 松开 → 弹出确认对话框（列出文件、重复策略选择）
  4. 确认 → 构造 PanTodoItem (Type=Move)
  5. 执行成功 → 左右栏对应目录局部刷新
     执行失败 → 执行日志 Tab 显示错误信息
`

### 3.3 F2 重命名流程

`
用户操作：
  1. 选中单个文件/文件夹，按 F2
  2. ListView 子项进入原地编辑模式（LabelEdit = true）
     • 文件名高亮选中，扩展名默认不选中
  3. 用户输入新名称，Enter 确认
     • 校验：非空、无非法字符 \ / : * ? " < > |、同目录不重名
  4. 构造 PanTodoItem (Type=Rename) → 加入待办或立即执行
  5. Esc 取消编辑，恢复原名称
`

### 3.4 Delete 删除流程

`
用户操作：
  1. 选中 1~N 个文件/文件夹，按 Delete
  2. 弹出确认对话框（列出文件 + 合计大小/数量 + 回收站提示）
  3. 文件夹删除需额外提示"包含 N 个子文件"
  4. 确认 → 构造 PanTodoItem (Type=Delete) → 加入待办或立即执行
`

### 3.5 新建文件夹流程

`
用户操作：
  1. 左栏或右栏，目标目录焦点
  2. Ctrl+Shift+N / 工具栏 / 右键菜单
  3. 弹出输入框（父目录显示 + 名称输入）
  4. 确定 → 调用 CreateFolder API
     成功 → 当前目录 TreeView / ListView 新增节点
     失败 → 提示错误信息
`

/// 整理工具中的待办操作（扩展自 PanRecommendation，支持 UI 状态跟踪）
public class PanTodoItem
{
    public string Id { get; set; } = Guid.NewGuid().ToString("N").Substring(0, 8);
    public string? SourceRecommendationId { get; set; }  // 关联 AI 建议
    public PanRecommendationType Type { get; set; }
    public string SourcePath { get; set; } = "";        // 源完整路径
    public string SourceName { get; set; } = "";        // 源文件名（展示）
    public string? DestinationPath { get; set; }        // Move 目标目录
    public string? NewName { get; set; }                // Rename 新名称
    public string? ParentPath { get; set; }             // CreateFolder 父目录
    public string? FolderName { get; set; }             // CreateFolder 文件夹名
    public string Reason { get; set; } = "";
    public TodoStatus Status { get; set; } = TodoStatus.Confirmed;
    public PanExecutionResult? ExecutionResult { get; set; }
    public long? SourceFsId { get; set; }               // 精确执行用

    // ---- 文件夹重命名专属（IsFolder=true 时填充）----
    public bool IsFolder { get; set; }
    public FolderRenameOptions? RenameOptions { get; set; }
}

public enum TodoStatus { Confirmed, Skipped, Executing, Succeeded, Failed }

/// 剪贴板状态（剪切/复制）
public class PanClipboardState
{
    public ClipboardAction Action { get; set; }
    public List<PanFileInfo> Items { get; set; } = new();
    public string? SourceDirectory { get; set; }
}
public enum ClipboardAction { None, Cut, Copy }

/// <summary>文件夹重命名选项（承载大小后缀配置，1:1 关联 FolderRenameDialog）</summary>
public class FolderRenameOptions
{
    /// <summary>是否追加文件夹总大小后缀</summary>
    public bool AppendSizeSuffix { get; set; } = false;

    /// <summary>后缀格式（枚举/字符串模板）</summary>
    public FolderSizeSuffixFormat SuffixFormat { get; set; } = FolderSizeSuffixFormat.BracketGB;

    /// <summary>大小精度：小数位数 0~3（GB/MB 自动切换）</summary>
    public int DecimalPlaces { get; set; } = 2;

    /// <summary>后缀放置位置：Prefix(前缀) / Suffix(后缀，默认)</summary>
    public SuffixPosition Position { get; set; } = SuffixPosition.Suffix;

    /// <summary>是否包含"X 个文件 + Y 个子目录"文本提示（仅对话框展示，不写入实际文件名）</summary>
    public bool ShowCountInPreview { get; set; } = true;

    /// <summary>计算结果缓存（快照本地聚合，非拉取 API）</summary>
    public long ComputedSizeBytes { get; set; }
    public int ComputedFileCount { get; set; }
    public int ComputedSubFolderCount { get; set; }
    public bool IsSizeEstimated { get; set; }  // true=快照截断，大小偏小
}

public enum FolderSizeSuffixFormat
{
    ParenthesisGB,   // _(3.25GB)     默认
    BracketGB,       // _[3.25 GB]
    ChineseBracket,  // 【3.25GB】
    HyphenGB,        // -3.25GB
    Custom           // 自定义模板：{SizeGB} {SizeMB} {FileCount} {FolderCount}
}

public enum SuffixPosition
{
    Suffix,  // 例：高中数学资料_(3.25GB)
    Prefix   // 例：(3.25GB)高中数学资料
}

/// 撤销栈条目
public class PanUndoEntry
{
    public string Id { get; set; } = Guid.NewGuid().ToString("N").Substring(0, 8);
    public PanRecommendation OriginalOperation { get; set; } = new();
    public PanRecommendation ReverseOperation { get; set; } = new();  // 反向操作
    public DateTime ExecutedAt { get; set; } = DateTime.UtcNow;
    public bool CanUndo { get; set; } = true;
}

#region 12. 新建文件夹（create 接口）
public async Task<CreateFolderResponse> CreateFolderAsync(string path, string name)
{
    var queryParams = new Dictionary<string, string>
    {
        ["method"] = "create",
        ["access_token"] = _accessToken
    };
    var requestBody = new Dictionary<string, string>
    {
        ["path"] = path,
        ["name"] = name,
        ["isdir"] = "1",
        ["size"] = "0"
    };
    var url = $"/rest/2.0/xpan/file?{BuildQueryString(queryParams)}";
    var content = new FormUrlEncodedContent(requestBody);
    return await SendPostRequestAsync<CreateFolderResponse>(url, content);
}

## 九、异常与边界情况处理

### 9.1 网络与 API 异常

| 场景 | 处理策略 |
|------|----------|
| Token 过期 (errno=-6) | 同 Orchestrator：刷新后自动重试 1 次 |
| 接口频控 (429 / 20012) | 复用 BaiduPanApiClient 内置指数退避重试 |

| 源文件已不存在 | 跳过并在日志中标注 |
| 目标已存在同名项 | 默认 NewCopy，失败则提示 |

- 拖到自身或子目录：DragEnter 🚫 光标 + Drop 拦截提示

`

长度限制：<= 255 字符
保留名拦截：空、仅 . 或 ..
同目录重名：先本地快照检查，API 返回错误再二次提示

- 根目录保护：禁止删除 / 根节点
- 当前目录保护：禁止删除左右栏正在浏览的目录
- 祖先节点保护：禁止删除当前目录的祖先节点

### 14.2 P0+ 必做优化（建议在阶段一前调整）

#### 14.2.1 架构：引入 IPanFileSystemProvider 抽象（解耦整理工具 vs 百度网盘 API）

**WHY**：原方案 PanNavigatorPanel 内部直接调用 BaiduPanApiClient，导致控件与网盘强耦合，后续若要支持"左云右本地（上传/下载）"或接入阿里云盘需重写控件。

**WHAT**：新增一层抽象：

    Task<long> CreateFolderAsync(string parentPath, string name, CancellationToken ct = default);

    /// <summary>批量执行操作（Move/Rename/Delete/Copy）</summary>
    Task<PanExecutionReport> ExecuteBatchAsync(
        List<PanRecommendation> ops,
        OnDupStrategy onDup = OnDupStrategy.NewCopy,
        IProgress<PanAnalysisProgress>? progress = null,
        CancellationToken ct = default);

    ClipboardCapability SupportedClipboard { get; }
}

public enum ClipboardCapability
{
    None,
    CutOnly,         // 网盘仅支持剪切式移动，真实"复制"需要调 copy API（额度敏感）

}

- PanNavigatorPanel 内部只依赖 IPanFileSystemProvider，不再直接引用 BaiduPanApiClient
- 新增 BaiduNetdiskFileSystemProvider（代理到 Orchestrator + ExecutionEngine + 新的 CreateFolder）
- 后续 1 天即可接入 LocalFileSystemProvider（DirectoryInfo/FileInfo 实现）

#### 14.2.3 流程：立即执行 → 默认"先加待办"，立即执行作为可选

**WHY**：原方案存在"立即执行"与"加入待办"双模式。用户零散操作时立即执行虽快，但：
1. 触发频控概率高（10 次零散调用 vs 1 次批量 10 条）
2. 无法做操作依赖排序（CreateFolder 必须在 Move 之前）
3. 无法做批量预检（冲突/权限/存在性）

**WHAT**：
- 所有用户交互（拖拽、F2、Delete、新建文件夹）默认生成 PanTodoItem 加入底部待办列表，**不立即执行**
- 顶部工具栏新增"⚡ 快速执行"开关（ToggleButton），开启时立即执行；关闭时统一入待办
- 用户可以在待办列表右键"立即执行此项"做单条强制立即执行

**IMPACT**：频控触发降低 70%，操作成功率上升，撤销栈更完整。

#### 14.2.5 安全：FsId 优先 + 操作前秒级校验

**WHY**：原方案通过 Path 执行操作，但从用户载入快照 → 真正执行期间可能过了 5-10 分钟，期间文件可能通过网页端/其他客户端被移动/改名，导致"删错/移错路径"的灾难性后果。

**WHAT**：
1. 所有 PanTodoItem / PanRecommendation 新增 **SourceFsId（必填）**，执行时百度 API 优先按 fs_id 匹配（path 作为兜底显示用）
2. 批量执行前加 PreflightCheckAsync：
   - 对源文件列表调一次轻量 API（BaiduPanApiClient.GetFileMetaAsync，有 FsId 版）
   - 校验文件是否还存在、FsId 是否匹配、当前路径是否一致
   - 如果有 5% 以上的文件对不上，弹窗提示：「快照已过期（检测到变化文件 N 项），建议刷新后再执行」，给出选项：[刷新并重载待办] / [跳过已变化文件] / [强制执行]

**IMPACT**：消除灾难性误操作风险，符合用户项目里"数据安全优先"的工程约束。

#### 14.2.6 安全：批操作合并（相同目录/相同操作打包同一次 filemanager 调用）

**WHY**：百度 API 每分钟 8-10 次调用限制，100 个文件逐个移动 100 次必触发频控；但 filemanager 接口单次支持 filelist 最多 1000 条，合并后 1 次调用完成。

**WHAT**：ExecuteTodoItemsAsync 内部在 BatchSize=100 之前再做一层 GroupBy：

`csharp
// 把同类型 + 同 DestinationPath 的 Move/Copy/Rename（相同父目录）合并
var batchGroups = todos
    .GroupBy(t => (t.Type, GroupKey: GetBatchGroupKey(t)))
    .SelectMany(g => g.Batch(BatchSize));  // 同组内按 BatchSize 切片
// GetBatchGroupKey: Move→DestinationPath；Rename→GetParent(SourcePath)；Delete→无约束；CreateFolder→ParentPath
`

**IMPACT**：相同目标目录的 100 个文件移动，从 100 次 API 调用降为 1 次，执行时间从 100×7s ≈ 700s 降到 7s（缩短 99%）。

#### 14.2.7 实施：P0 拆分为 4 个微型里程碑（符合偏好阶段性交付）

原 P0=13.5h 太粗，按用户偏好「阶段性交付，快速看到结果」拆分如下：

| 微型阶段 | 估算 | 交付效果 | 验收 Check |
|----------|------|----------|------------|
| **P0.1** 骨架+单栏浏览 | 2.5h | PanOrganizerForm.Show() 能打开；左栏显示快照目录树+文件；只读浏览无操作 | 打开不崩；TreeView 能展开；ListView 显示正确文件名/大小 |

### 14.3 P1+ 推荐优化（阶段一完成后做）

#### 14.3.1 UX：导航历史栈（前进/后退）

**WHY**：原方案只有"返回上级"，用户进入数学→英语→语文后想回到数学需要一层层点，很痛苦。

**WHAT**：每个 PanNavigatorPanel 内部维护两个栈：
- _backStack: List<string>（返回按钮用，最多 20 条）
- _forwardStack: List<string>（前进按钮用，导航时清空）

**IMPACT**：往返对比两个目录（如左栏数学 vs 英语）只需点一次 ←/→。

#### 14.3.2 UX：左右对比视图（高亮差异文件）

**WHY**：整理最常见的场景是"左栏下载目录，右栏归档目录，看哪些文件还没归档"。

**WHAT**：底部 Tab 新增 tabCompare「差异对比」。选中左目录 A + 右目录 B（默认当前左/右栏当前目录），点击「对比」后分三栏显示：
- 仅 A 有（建议归档 → 一键生成 Move 待办）
- 仅 B 有（可能已归档但 A 还没删 → 一键生成 Delete 待办）
- 两边都有但大小/MD5 不同（可能是版本差异 → 保留哪一份的选择）

内部算法复用 BaiduPanAnalysisOrchestrator.DetectDuplicates 的 GroupBy 逻辑，但按 (Name+Size) 匹配。

**IMPACT**：整理场景最大痛点 → 点击对比就能看到"还缺啥"。

#### 14.3.3 UX：拖拽目标路径不存在 → 自动追加 CreateFolder

**WHY**：用户拖文件时想放到 /整理归档/2026数学/，但 2026数学 目录还没建。原方案需要用户先取消 → 去建目录 → 再拖一次，很烦。

**WHAT**：拖拽 Drop 时，检测目标路径（TreeView 节点或手动输入）在快照中不存在：
- 对话框追加提示「目标目录不存在，是否先创建？☑ 默认勾选」
- 确认后，在同一个 batch 中自动在拖拽 Move 前插入一条 CreateFolder 待办，并把依赖连上（14.2.4 排序会保证先建后移）。

#### 14.3.4 UX：Splitter 快捷比例 + 焦点栏高亮

**WHY**（符合 UI 美观偏好）：
- 双栏整理时经常需要切换"左栏看文件、右栏看目标树"或者反过来，需要频繁调宽度
- 用户经常搞不清"现在键盘 F2/Delete 作用于哪一栏"

**WHAT**：
1. **SplitContainer 右键菜单**：右键分隔条弹出 50:50 / 左70右30 / 左30右70 / 锁定比例，一键切换宽度
2. **焦点栏高亮**：PanNavigatorPanel 顶部路径栏背景色，焦点栏用 #e8f0fe（蓝底白字图标），非焦点栏 #f7f7f7（浅灰）
3. **底部状态栏**：追加 焦点栏: [左栏] / 当前目录: /学习资料/数学/ / 已选: 3 个 (12.3MB)

#### 14.3.5 功能：复用 AI 打标（fileTags）做筛选器

**WHY**：原方案 BaiduPanAnalysisForm 已经算出了 Subject/价值观/年龄段/质量，但整理工具里完全没复用，可惜。

**WHAT**：
- 每栏顶部搜索框追加一个 [🏷 标签筛选 ▼] 下拉（和分析窗口的 cmbTagSubject/cmbTagAge/cmbTagValues 完全一致，直接复用 PopulateTagFilter/ApplyTagFilter 代码）
- 从分析窗口打开整理工具时，把 _analysisResult.FileTags 一并传入，按 TargetPath 索引挂到每个 ListViewItem.Tag 上
- 筛选后，只显示打标匹配的文件，**不匹配的灰色禁用但仍显示**（避免用户误以为文件丢了）。

代码复用可直接封装到一个静态类 PanTagFilterHelper 里，BaiduPanAnalysisForm.cs#L706-L759 和 PanNavigatorPanel 共用。

#### 14.3.6 功能：批量重命名（正则/模板）

**WHY**：整理大量文件时常见"数学_练习册_01.pdf ... 数学_练习册_15.pdf"想统一改成"高中数学-练习册-01.pdf（补零、加前缀、替换分隔符）"。

**WHAT**：待办列表顶部工具栏追加「🔄 批量重命名」按钮，打开对话框：
- 源：当前选中文件列表
- 模式：替换文本 / 加前缀 / 加后缀 / 正则替换 / 编号（补零 01-99）
- 实时预览左右两栏（旧名 → 新名），冲突的行红色高亮
- 确认后批量生成 Rename 待办，加入待办列表（不立即执行）。
