### 1.2 真实数据核对

当前用户 `钦伊` 的 `reading_time.json`：98 条记录、94 份文档、3 个日期（2026-10-29 \~ 10-31），路径呈多级目录（如 `E:\Tools\000个人\RAZ\00.RAZ绘本PDF+音频\level A 99个\`），适合按目录分组。

### 1.3 必须先解决的问题

1. **留存上限过小**：`PdfReadingTimeStore.MaxRecords = 800`，按当前“94 本 × 每天 1 条”估算，仅够 8.5 天，无法支撑月度矩阵。需改为按天数保留。
2. **无读取全量记录的接口**：`GetSnapshot` 只返回 4 个汇总值，打卡表需要明细。需新增 `GetRecords()`。
3. **误触阅读被计入**：真实数据中存在 13 秒的记录，直接参与打卡会产生“假打卡”。需引入“有效打卡阈值”。
4. **跨用户串数据**：`PdfReadingTimeStore` 由 `PdfReaderForm` 第 577-582 行从根容器解析，构造时固化用户目录（`PdfReadingTimeStore.cs` 第 65-70 行），而切换用户只改 `AppPaths.CurrentUserDir`（`LearningForm.cs` 第 2783 行），不重建容器。切换用户后报表仍读上一用户数据；`PdfReadingPositionStore`（`ServiceCollectionExtensions.cs` 第 270 行注册为 Singleton）同样存在该问题。必须在 P0a 修复。
5. **清单与入口语义不清**：`_allFiles` 含图片且来自递归枚举；单独打开文件时该清单可能为空或仍是上一次目录的旧数据。报表必须明确“只统计 PDF”，并定义单文件回退范围，否则会把图片算进来或统计到旧目录。

## 2. 目标与非目标

### 2.1 目标

- 以阅读器**当前文件夹树根**为分组基准，按相对目录层级生成打卡表。
- 阅读对象仅限 **PDF**；阅读器清单中的图片（jpg/jpeg/png/bmp/gif）不参与统计。
- 同一份报表包含两页：**目录汇总页** + **日历矩阵页**；矩阵默认勾选显示，可切换为分钟数字。
- 支持按月切换、有效打卡阈值可调、显示范围可切换（全部 / 仅有记录）、目录可折叠。
- 严格的**用户隔离**：报表只读取当前登录用户的阅读记录。
- 支持 **A4 横向分页打印**（重复表头/页脚/页码，必要时自动分两段）、导出 **Excel（双工作表）**、导出 **HTML（离线可打印）**。

### 2.2 非目标

- 不做 PDF 内部书签章节级打卡（现有数据只到“PDF + 日期”粒度，需另建页级记录，本期不做）。
- 不改数据库结构、不做云同步、不做多人对比。
- 不引入新的数据采集逻辑（沿用现有 30 秒心跳口径）。
- 不对历史误归属数据做自动迁移（原因见第 11 节）。

## 3. 统计口径（需在 UI 上明示）

| 口径        | 定义                                                                                 |
| --------- | ---------------------------------------------------------------------------------- |
| 阅读对象      | 仅 PDF（`.pdf`）；以 `reading_time.json` 的 `DocPath` 扩展名为准，图片等其他类型一律忽略，即使出现在 `_allFiles` 或历史记录中            |
| 有效打卡      | 某 PDF 在某个自然日累计秒数 ≥ 阈值（默认 60 秒，可在 0-3600 秒间调整；0 表示打开即算）                              |
| 打卡天数      | 统计区间内满足“有效打卡”的天数                                                                   |
| 累计时长      | 统计区间内该 PDF 全部秒数之和（含未达阈值的零碎时长）                                                         |
| 覆盖率       | 打卡天数 / 统计区间“已过天数”。已过天数 = `[区间起点, min(区间终点, 今天)]` 的天数；为 0 时覆盖率记 0，并禁用未来月份           |
| 未读 / 未达标  | “未读”= 区间内无任何秒数；“读了未达标”= 有秒数但不足阈值。两者不得合并显示                                          |
| 当前连续（文档级） | 走查**全量历史**（不受区间起点限制），基准日 = `min(区间末日, 今天)`；基准日无打卡则从基准日前一天回溯；最近打卡日距基准超过 1 天记为 0（断签） |
| 目录级连续     | 组内任一 PDF 在当日达标即算该目录当日打卡，回溯规则同上                                                      |
| 总体连续      | 当前根目录内任一 PDF 在当日达标即算；报表中命名为“总体连续”，**不跨根目录**                                         |
| 目录归属      | 以根目录为基准的相对路径（大小写不敏感）。根目录默认取 PDF 清单的公共根目录（图片不参与），可手动改用其他目录     |
| 目录显示      | 汇总/矩阵的目录列展示**相对路径**（根层显示“（根目录）”），过长时截断并在 Tooltip 显示完整路径，避免不同分支同名目录混淆               |
| 文件失效      | 有历史记录但磁盘文件不存在：先在同级目录按文件名唯一匹配 → 再在根目录内全局唯一匹配（命中标“已重命名”）；无匹配或多候选则归入「已失效文件」组          |
| 显示范围      | 界面只保留一个开关：“全部 / 仅有记录”，映射 `IncludeUnread`；默认“仅有记录”，不再出现两个含义相反的复选框                   |
| 阈值与显示记忆   | 阈值（秒）、矩阵显示模式（勾选/数字）、显示范围、折叠状态按用户持久化到用户设置文件，不写入全局 `appsettings.json`                |
| 时长来源说明    | 仅统计“阅读器窗口处于前台且已打开该文档”的停留时间，不含后台阅读；UI 底部需给出该说明                                      |

        ┌─────────────────────────────────────────────┐
        │ PdfCheckInLayoutModel + HtmlBuilder（Core） │
        │ 列宽 / 颜色分档 / 分页计划 / HTML 字符串      │

分层原则：

- 聚合、布局、分页计划、HTML 生成全部落在 Core；其中 HTML 为纯字符串构建，便于 Core.Tests 做快照测试。
- Excel（EPPlus 8.6）与 `PrintDocument` 留在 WinApp，避免 Core 承担平台绘制逻辑。
- 说明：`LearningAssistant.Core.csproj` 目前**已经引用 EPPlus 8.6.0**（此前文档“Core 不引用 Office 包”表述不准确）；本期不为 Core 新增 Office 相关代码路径。
- 报表模型为只读 DTO；矩阵列宽、颜色分档、分页计划由 Core 的布局模型统一输出，界面、打印、HTML 只负责绘制，避免三套实现漂移。

### 5.3 聚合服务（新增）

文件：`LearningAssistant.Core/Services/Pdf/PdfReadingCheckInService.cs`

```csharp
public sealed class PdfReadingCheckInService
{
    public PdfReadingCheckInService(PdfReadingTimeStore store, ILogger<PdfReadingCheckInService>? logger = null);

    /// <summary>构建打卡表报表（含布局模型）；纯计算，无 UI 依赖。</summary>
    public PdfReadingCheckInReport Build(PdfReadingCheckInRequest request);
}
```

算法要点（伪代码）：

```text
1. 规范区间：
   - Start/End 取日期部分；End = min(End, 今天)；若 Start > End，返回空报表；
   - 已过天数 elapsedDays = (End - Start).Days + 1；elapsedDays <= 0 时覆盖率一律 0。
2. 读取明细：
   - 区间明细：store.GetRecords(Start, End)；
   - 连续天数：store.GetRecords() 全量读取，仅用于回溯，不参与区间统计。
3. 构造候选 PDF：
   a. request.Documents 中扩展名为 .pdf 的路径（图片等其他类型一律丢弃）；
   b. 区间明细中位于 RootPath 下、且扩展名为 .pdf 的路径；
   c. 大小写归一化后按 FullPath 去重；
   d. 对 Exists=false 的路径做重命名兜底：
      - 先在同级目录按文件名唯一匹配；
      - 再在 RootPath 内全局唯一匹配；
      - 命中则合并到真实文件并标记 RenamedMatched；多候选或零候选保持失效。
4. 过滤：
   - 不在 RootPath 下的 PDF 不进入报表，但去重后计入 Totals.OutOfScopeDocumentCount；
   - IncludeUnread=false 时丢弃 Status=Unread 的 PDF；
   - IncludeMissing=false 时丢弃 Exists=false 的 PDF。
5. 目录分组：
   - 相对路径 = Path.GetRelativePath(RootPath, DirectoryName)（异常时回退为空串）；
   - 根层相对路径为 ""，DisplayPath = "（根目录）"；其余 DisplayPath = 相对路径（过长由 UI 截断 + Tooltip）；
   - 目录按 StringComparer.Create(CultureInfo.CurrentCulture, true) 排序；
   - 已失效文件归入保留组 relativePath = "__missing__"，显示名「已失效文件」，排在最后。
6. 逐 PDF 统计：
   - DaySeconds：按日期聚合同一路径的多条记录（大小写不敏感合并）；
   - Status：无秒数 = Unread；有秒数但无任何一天达标 = UnderThreshold；否则 CheckedIn；
   - CheckInDays：DaySeconds 中秒数 >= MinSeconds 的天数；
   - TotalSeconds / LastCheckInDay / Coverage（elapsedDays 为 0 时记 0）；
   - CurrentStreak：全量历史从基准日 min(End, 今天) 回溯。
7. 目录汇总：组内 PDF 日期集合“或”合并；打卡天数按区间，连续按全量历史。
8. 总体汇总：所有组再合并；输出 OverallCurrentStreak（当前根目录范围）；BestStreak 取组内最大值。
9. 输出不可变 DTO：目录按 CurrentCulture、PDF 按文件名排序。
10. 生成 PdfCheckInLayoutModel：固定列宽 + 日期列宽、颜色分档、打印分段模式与“页 -> 行”计划；
    - 若 31 列单页时单元格宽度 < 5.5mm，自动切换 TwoSegments 并在报表中标记，供 UI 提示。
```

性能与边界：

- 时间复杂度 `O(记录数 + PDF 数 × 天数)`，日期区间最大 31 天，数据规模在千级，同步执行即可；UI 侧仍放到后台线程避免卡顿。
- 所有路径比较使用 `StringComparer.OrdinalIgnoreCase`；`Path.GetRelativePath` 跨盘符场景需 try/catch 回退。
- `RootPath` 不存在（如移动磁盘未连接）时返回带 `RootUnavailable` 标记的空报表，UI 显示错误横幅并禁用导出。
- 无记录且无文件、且未开启“全部”的空目录不生成分组。
- `_allFiles` 来自递归枚举，超大目录下由 UI 传入清单，服务不做二次磁盘扫描（单文件回退除外，见 6.1）。

### 7.3 分页打印（PrintDocument，WinApp）

- A4 横向，`Margins = 10mm`；正文用 `System.Drawing` 绘制表格（不依赖界面控件截图）。
- 打印顺序：汇总页 → 矩阵页；按钮提供「全部 / 仅汇总 / 仅矩阵」三种范围。
- 排版先行：由 `PdfCheckInLayoutModel.Pages` 给出“页 → 行”计划，页数与页码在打印前即确定，不做两遍排版。
- 绘制单位：`e.Graphics.PageUnit = GraphicsUnit.Millimeter`；注意 `PrintPageEventArgs.MarginBounds` 仍以 1/100 英寸表示，需按 `0.254` 换算成毫米，且不要与 `PageUnit` 混用。
- 可读性兜底：5 个固定列约占 90mm，31 个日期列每列约 6.0mm；默认字号不低于 6.5pt。若计算宽度 < 5.5mm，自动切换 `TwoSegments`（1-15 / 16-31），并在预览顶部提示。
- 分页规则：
  - 每页重复标题区与表头；
  - 汇总页：目录分组尽量不跨页；单组超过一页时允许拆分并标「（续）」，保证表头后至少 2 行同页，避免大面积空白；
  - 矩阵页：按可用高度计算每页行数，固定列与日期表头每页重复；
  - 页脚：`第 x 页 / 共 y 页 · 生成于 yyyy-MM-dd HH:mm`。
- 预览：`PrintPreviewDialog` 以 `ShowDialog(this)` 打开并置顶，避免被阅读器遮挡；异常（打印机不存在）Toast 提示，不阻塞窗口。
- 整个导出/打印期间阅读计时保持暂停，结束后恢复。

## 10. 测试与验收

### 10.1 单元测试用例（Core.Tests）

- `GetRecords` 返回副本：调用方修改返回值不影响 store 内部数据；`Add` 后再次读取可见。
- 同一路径多条记录合并：跨大小写差异路径视为同一 PDF。
- 阈值边界：59 秒不计打卡、60 秒计打卡；阈值为 0 时任意秒数计打卡。
- 三种状态：无记录 = Unread；有记录但所有日期都未达标 = UnderThreshold；任一天达标 = CheckedIn。
- 阅读对象类型：PDF 记录进入报表；图片（jpg/png）及不支持的类型记录一律忽略，即使出现在 `Documents` 与 `GetRecords` 中。
- 目录分组：多层相对路径正确；根层归入「（根目录）」；相对路径展示避免同名目录混淆；中文目录按 CurrentCulture 排序。
- 打卡天数去重：一天内多次累加不重复计天。
- 连续计算：区间内无记录但历史连续 → 连续正常显示；连续 5 天后中断 2 天 → 0；跨月边界正确；区间末日无记录时从前一天回溯；当月以今天为基准。
- 覆盖率：当月按已过天数；历史月按整月；区间起止晚于今天时覆盖率 0 且不抛异常（除零保护）。
- 用户隔离：切换 `CurrentUserDir` 后，同一 store 实例读写各自目录，互不可见。
- 显示范围：`IncludeUnread=false` 排除未读 PDF；`IncludeMissing=false` 排除失效文件。
- 重命名兜底：同级唯一匹配成功；根目录全局唯一匹配成功；多个同名候选时保持失效，不误并。
- 区间过滤：区间外记录不进入报表；未来日期不进入矩阵列；根目录外 PDF 计入 OutOfScopeDocumentCount 且不进报表。
- 留存裁剪：730 天前记录被淘汰；20000 条硬上限生效且不丢最近数据；裁剪后文件内容同步缩减。
- 月份边界：2 月（28/29 天）、31 天月份矩阵列数正确。
- 布局分页：页计划数量确定且每页含表头；31 列宽度不足时自动切换 TwoSegments；HTML 输出快照比对（分档变化需显式更新快照）。

### 10.2 WinApp 导出测试（`LearningAssistant.Tests`，可选但建议）

## 12. 验收标准

1. 打开任一文件夹（或单个文件，仅统计 PDF）后，可从「更多 → 阅读辅助 → 阅读打卡表…」生成当月报表，窗口内含汇总页与矩阵页。
2. 报表数字可通过 `reading_time.json` 中的 PDF 记录手工核对一致（目录合计、文档打卡天数、时长）；图片记录一律不计入。
3. 有效打卡阈值默认 60 秒且可按秒调整，误触阅读不会被计为打卡；“未读”与“读了未达标”分别展示。
4. 连续天数按全量历史、基准日取 `min(区间末日, 今天)` 计算；历史月份与当月结果均不误报；未来月份覆盖率 0 且翻页禁用。
5. 切换用户后，报表只读取当前用户数据，不与上一用户串号；朗读断点不受影响。
6. 显示范围只有一个开关，行为与模型字段一致；目录折叠行在矩阵中有明确的汇总语义。
7. 打印预览为 A4 横向分页：表头与页脚页码在每页重复，目录分组不无故跨页；31 列不可读时自动分两段；屏幕、打印、HTML 三端分档一致。
8. Excel 导出含「目录汇总」「打卡矩阵」两个工作表，条件底色正确；HTML 离线打开可直接打印；导出文件名不含非法字符。
9. 打开报表/打印预览不会增加阅读时长统计。
10. 新增单元测试全部通过；`dotnet build LearningAssistant.slnx` 无新增警告与错误。
