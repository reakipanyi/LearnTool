# PDF 阅读模块竞品对比与优化路线

> 对比日期：2026-10-29
> 对比口径：本项目侧依据代码与《功能清单与操作入口清单》整理；竞品侧依据产品功能描述整理，未做实测。
> 对比对象：译点通、墨析智能文献阅读器、Modu 默读、SumatraPDF-plus、Snap&Read、Wonder Reader、Speechify。

## 一、总判断

本项目的 PDF 模块定位不是“阅读器”，而是 **AI 学习型 PDF 工作站**：

- **领先区**：文档级 AI（检索问答 / 大纲 / 学习笔记 / 标注聚类 / 术语表润色）、标注→学习项→SM-2 的学习闭环、外部配套音频工程。
- **落后区**：听读体验（点读闭环、朗读同步高亮、连续朗读）、阅读器基本功（多格式、页面管理、离线词典、无障碍、移动端）。

一句话：**在“学”和“听配套音频”上处于第一梯队，在“读”和“点读听书”上还差一代。**

## 三、逐款对位：差距在哪

### 3.1 译点通（最直接对标）

- **它强在**：唯一把“点读→整句朗读→译文浮层→跟读打分”做成闭环的产品，离线音色免费。
- **你的现状**：三块零件都齐，但没串起来：
  - 自动框选点开只走翻译（`PdfAutoHighlightManager.HandleHighlightSelectedAsync`）；
  - 顶部译条有“朗读原文”（`PdfTopTranslationBar`）；
  - 跟读窗口已具备逐句合成、自动录音与参考评分（`SentenceShadowingForm`）。
- **缺口**：三者未联动；ASR 仅支持 en-US，中文书只能给“参考分”。

### 3.2 墨析

- **它强在**：单界面“阅读+翻译+朗读+批注+区域识别+AI 解读+问答”零切换，外加页面对比、护眼、阅读时长统计。
- **你的现状**：七项核心全覆盖且更强（多出术语表、检索问答、闪卡、配套音频、批量 OCR 智能整理）。
- **缺口**：页面对比、阅读时长、护眼这类低成本辅助，以及“单界面零切换”的产品化包装。

### 3.3 Modu 默读

- **它强在**：跨平台、多格式、WebDAV/S3 同步、词典百科、向量索引、离线 OCR 多页。
- **缺口**：格式单一（仅 PDF）、无同步、无词典。

### 3.4 SumatraPDF-plus

- **它强在**：轻量启动、PP-OCR 中文精度、输出可搜索 PDF、逐词朗读高亮、双击查词、页面管理（裁切/去斜/插删/提取）。
- **你的现状**：标注与 AI 能力远超它。
- **缺口**：阅读器基本功与启动性能。

### 3.5 Snap&Read

- **它强在**：动态文本难度分级（独门）、100+ 语种、阅读引导线/色层、引文、年级可读性分析。
- **缺口**：教育辅助向基本空白。

### 3.6 Wonder Reader

- **它强在**：macOS 无障碍标杆（VoiceOver 位置联动 + 本地 AI 免费）。
- **缺口**：界面为位图渲染，读屏软件基本不可用，属结构性短板。

### 3.7 Speechify

- **它强在**：TTS 工业化（1000+ 音色、60+ 语言、4.5x、逐词高亮、全平台续听）。
- **你的现状**：“读得动但听不爽”：音色少、语速档位少、无连续朗读/自动翻页。

## 四、本项目独有优势（必须保留）

1. **文档级 AI**：检索式问答 + 大纲 + 学习笔记 + 标注按主题聚类 + 术语表强制润色。
2. **学习闭环**：高亮→学习项→SM-2→闪卡复习，竞品普遍缺失。
3. **配套音频工程**：目录扫描 + 正则/通配符 + AI 匹配 + AB 复读 + 不变调变速 + 按书续播 + 配置导入导出，7 款中无对位。
4. **标注深度**：马赛克/聚光灯/激光笔/放大镜/插入图片/检查清单，接近 Notability 级。
5. **本地优先**：Tesseract + Kokoro 离线可跑，无账号、无云端。

## 六、优化路线

| 优先级 | 事项 | 复用的现有资产 |
|---|---|---|
| **P0** | **点读闭环**：自动框点击 → 朗读整句 → 译文浮层 → 一键跟读 | 自动框选 + 顶部译条 + 跟读窗口，只差事件串联 |
| **P0** | **朗读同步高亮**：句子级高亮随朗读推进；整篇连续朗读+自动翻页+断点续听 | `IPdfService.GetTextLines` 已有行坐标；TTS 逐句合成 |
| P1 | 离线词典双击查词；翻译语种扩展 | 与现有翻译/OCR 管线同层 |
| P1 | 页面管理：裁切/去斜/插删页/导出可搜索 PDF | 旋转已具备，补 PDFium 写回 |
| P1 | 阅读辅助：行宽/字距/色层/引导线/护眼；阅读时长统计、页面对比 | 纯视图层，成本最低、观感提升最大 |
| P2 | 无障碍（UIA 文本层暴露）、跨设备同步、移动端/iPad 手写、PPTX/HTML 课件、多模态截图问答 | MAUI 迁移已有评估文档 |

## 七、P0 实施方案与验收标准

### 7.1 P0-A 点读闭环

**目标**：在自动框选模式下，点击任意文本框即可完成“朗读整句 → 显示译文 → 可一键跟读”。

**实施要点**

1. 句级取词：点击的框只提供起始文本；按当前页文本行坐标向后合并，直到句末标点（`.?!。？！`），跨行拼接时补空格/去连字符。
2. 朗读：调用现有 `IPdfTtsService`，语言按句内文字自动判定；播放期间该框显示“朗读中”态。
3. 译文：复用顶部译条，展示原文 + 译文，并保留“朗读原文 / 复制 / 关闭”按钮。
4. 一键跟读：译条新增“跟读此句”按钮，点击直接打开跟读窗口并定位到该句；无英语识别器时仍走“参考分”。
5. 关闭或切换页面时停止朗读，避免残留音频。

**验收标准**

- 点击文本框后 1 秒内开始朗读，且读出的是完整句子而非框内碎片。
- 译条同时显示原文与译文；重复点击同一框不会叠加播放。
- 点“跟读此句”进入跟读窗口，句子列表定位到所点句。
- 无文本框、无文本层、TTS 不可用三种边界均有明确提示，不崩溃。

### 7.2 P0-B 朗读同步高亮 + 连续朗读

**目标**：朗读时高亮跟随当前句子；支持从当前页连续读完整篇，自动翻页，关闭后可续读。

**实施要点**

1. 句子模型：用 `IPdfService.GetTextLines` 拿到行坐标，按标点合并为句子，生成 `(文本, 矩形集合, 页号)` 列表；扫描页走现有 OCR 版面结果。
2. 播放调度：逐句调用 TTS 并播放，一句播完自动推进下一句；句子切换时重建高亮覆盖层（复用标注图层的绘制通道，但独立开关，避免污染标注数据）。
3. 连续朗读：页末自动进入下一页第一句；到达文档末尾停止。提供播放/暂停、上一句/下一句、停止、语速控制。
4. 断点续听：按“文档路径 + 修改时间”持久化 `(页号, 句号)`，重新打开同一文档时提示续读或自动定位。
5. 夜间模式与双页模式下高亮坐标必须走同一套仿射变换，避免偏移。

**验收标准**

- 朗读时高亮准确落在当前句（含跨行句），切换句子无闪烁、无错位。
- 连续朗读可跨页自动翻页，翻页后继续朗读，不重复、不跳句。
- 关闭文档再打开，可从上次句继续；换文档不串断点。
- 暂停/恢复、上一句/下一句、停止均即时生效，无残留音频。

### 7.3 实施顺序

1. P0-A（点读闭环）→ 编译 + 手工验证 → 提交。
2. P0-B 句子切分与坐标 → 同步高亮 → 连续朗读 → 断点续听 → 编译 + 手工验证 → 提交。
3. 每步只改必要文件，保留既有注释与行为；新增逻辑优先放入 Core 层以便单元测试。
