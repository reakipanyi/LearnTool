要将之前的战略构想从“概念”落地为“可执行的技术方案”，我们需要从**数据模型（元建模）**、**功能逻辑（工作流）**、**交互机制（UI/UX逻辑）**、**模块耦合（事件驱动）** 四个维度进行立体化拆解。

以下是一套完整的**细化与逻辑重组方案**：

---

### 维度一：数据层细化——打造“动态实体-属性-值”（EAV）元模型

要打破“预设字段”的限制，必须重构底层数据存储逻辑。

| 逻辑层级 | 设计思路 | 具体实现方案 |
| :--- | :--- | :--- |
| **1. 模板（Template）** | 用户自定义“知识类型”的骨架 | 新增 `TemplateEntity` 表，允许用户创建模板（如“编程函数”、“历史人物”），模板包含多个**动态字段**（字段名、字段类型[文本/数字/日期/代码块]）。 |
| **2. 实例（Instance）** | 具体的学习卡片 | 学习项不再绑定固定的类（如不再写死 `EnglishWord` 类），而是绑定 `TemplateId`。数据以 **JSON** 格式存储在 `ContentJson` 字段中（SQLite支持JSON查询）。 |
| **3. 字段索引化** | 保证检索性能 | 要求用户为模板设置 **1-2个索引字段**（如“名称”），系统自动提取JSON中的该字段值存入单独的 `IndexValue` 列，确保列表加载不卡顿。 |
| **4. UI动态渲染** | 界面自适应 | 学习界面不再硬编码控件。改为**动态表单生成器**：根据模板定义，在运行时动态生成标签（Label）和对应的文本框、数字选择器。 |


### 维度二：功能层细化——三大模块的逻辑闭环

#### 1. 多学科自定义学习（知识库逻辑）
- **原子化拆解逻辑**：用户导入长文本（如一篇论文）→ 点击“AI拆解” → 调用LLM提取核心概念 → 系统引导用户选择“拆解为1个模板实例”或“拆解为多个子卡片”。
- **双向知识图谱逻辑**：不追求复杂的图数据库。采用**标签继承 + 双向引用**：每个学习项有一个 `RelatedIds`（JSON数组）。在显示“当前项”时，底部自动拉取这组关联ID的标题作为“前序知识/后续应用”快速跳转。

#### 2. 多模态自适应间隔重复（复习引擎逻辑）
- **隐式评分机制（核心算法细化）**：废除每次手动点“正确/错误”的机制，引入 **“置信度衰减模型”**。
  - *监听事件*：用户查看卡片时的**停留时长**、是否点击了“详情折叠”、是否修改了笔记、是否在PDF中搜索了该关键词。
  - *权重计算*：停留时间短（<3秒）且无任何交互 → 隐式扣分（等效于质量评分 `Quality=2`）；修改了笔记内容 → 等效于 `Quality=5`（深度加工）。
  - *阈值触发*：仅当隐式评分极度不确定（波动大）时，才弹出一次“轻量级确认弹窗”要求显式打分，**将手动操作减少80%**。
- **动态干预（急诊室）逻辑**：在复习队列最上方设 **“临时置顶池”**。用户拖拽卡片进入此池，算法强制忽略 `NextReviewDate`，优先展示，且手动置顶的卡片复习间隔不纳入永久算法迭代（避免污染长期记忆数据）。

#### 3. 主动式PDF认知工作台（PDF逻辑）
- **双向锚定逻辑**：PDF选词右键 → “生成复习卡” → 系统自动抓取PDF元数据（书名、页码、坐标），存入新卡片的 `SourceRef` 字段。
- **结构萃取逻辑**：点击“生成大纲” → 调用LLM解析PDF目录（或全文） → 生成树形结构 → 存入独立 `OutlineCache` 表。用户点击大纲节点，触发 `PdfViewer.JumpToLocation(Page, Rect)`。
- **跨文档横向串联逻辑**：新增 **“项目（Project）”** 概念。用户创建一个“项目”（如“毕业论文”），拖拽多个PDF和自定义学习模板进去，系统将该项目内所有的高亮、批注、卡片汇聚成一个**独立的倒排索引**，支持跨文件语义搜索。


### 维度三：交互层细化——UI/UX的用户操作逻辑

不能把所有新功能堆满界面，需遵循 **“渐进式披露”** 原则。

| 界面区域 | 细化后的交互逻辑 |
| :--- | :--- |
| **主列表（左侧）** | 支持**多视图切换**：①树形目录（按学科分类） ②图谱模式（显示关联线） ③时间线模式（按最近复习/编辑排序）。 |
| **学习卡正面（中央）** | 采用**分栏对比模式**：左侧展示“原文/问题”，右侧展示“我的笔记/AI解析”。点击“AI解析”时，右侧自动流式输出，不影响左侧内容的阅读连续性。 |
| **PDF侧边栏（右侧）** | 增加 **“高亮广场”** ：显示当前PDF内所有高亮，并按颜色分类（红色=疑问，黄色=重点，绿色=已掌握）。点击任意高亮，PDF自动跳转。 |
| **复习交互** | 引入 **“主动回忆倒计时”**：展示答案前，强制等待3-5秒（可配置），并在屏幕中央显示巨大的倒计时数字，强制大脑进行提取练习。 |


### 维度四：模块“化学融合”的事件驱动逻辑（终极细化）

不能依靠“保存按钮”来联动，必须依靠**事件总线（EventBus）** 异步解耦。

1. **事件定义**：定义全局事件，如 `HighlighterCreatedEvent`（高亮创建）、`NoteUpdatedEvent`（笔记更新）、`ReviewCompletedEvent`（复习完成）。
2. **订阅与联动逻辑链**：
   - **链式反应A**：`PDF高亮` → **触发** → `隐式评分监听器`（给关联的复习卡加分） + `AI摘要监听器`（后台异步生成高亮文本的摘要存入备注）。
   - **链式反应B**：`自定义卡片保存` → **触发** → `向量化监听器`（调用本地Embedding模型将文本转为向量） + `关联推荐监听器`（计算向量余弦相似度，自动填充 `RelatedIds`）。
3. **冲突处理逻辑**：当AI自动生成的标签与用户手动修改的标签冲突时，**以用户最后一次手动修改为准**，AI只能作为“建议”在侧边栏显示，不可覆盖用户数据。


### 五、优先级执行路线图（基于逻辑依赖关系）

按照**“先建骨架，再通血脉，后长肌肉”**的逻辑排期：

| 阶段 | 核心任务 | 逻辑目标 | 交付物 |
| :--- | :--- | :--- | :--- |
| **Phase 1（骨架）** | 重构数据层：实现 **EAV动态模板** + **基础SQLite JSON存储**。 | 先让“万物皆可学”跑通。 | 可自定义字段的学习卡片界面。 |
| **Phase 2（血脉）** | 打通 **PDF双向锚定** + **事件总线**。 | 实现“划线即生卡”，让PDF不再孤立。 | PDF右键生成复习卡，且卡片带来源链接。 |
| **Phase 3（大脑）** | 升级复习引擎：植入 **隐式评分算法** + **关联推荐（向量相似度）**。 | 实现“越用越懂你”的自适应。 | 复习时不再频繁弹窗，关联知识自动推荐。 |
| **Phase 4（高维）** | 推出 **“项目工作台”** + **跨文档语义检索**。 | 面向深度研究者提供终极形态。 | 同时管理多文档和多卡片的聚合视图。 |

---

### 总结：如何检验这组细化需求的成败？

在上述逻辑中，请务必守住两条**不可妥协的逻辑红线**：
1. **离线优先**：AI（LLM）永远是“**外挂大脑**”而非“心脏”。所有核心CRUD（增删改查）和SM-2计算必须**不依赖网络**瞬间完成。
2. **用户主权**：凡是涉及“自动生成”、“自动关联”的功能，都必须提供 **“撤销/断开关联”** 的物理按钮。让用户感觉系统是**仆从**（随叫随到，绝不添乱），而不是**主人**（擅自决定学什么）。

按照这套细化的逻辑去写代码，你的产品在**知识工作深度**上将对AI学习机形成**代际碾压**。
