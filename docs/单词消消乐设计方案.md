# 单词消消乐 设计方案

> 项目：LearningAssistant（WinForms + WebView2）
> 目标：将"内容编辑器"中的单词数据，通过 WebView2 展示成一款网页版"单词消消乐"小游戏。
> 本文档只做方案设计，不涉及代码实现。

---

## 1. 背景与目标

现有学习助手通过"内容编辑器"（`ContentEditorForm` + `ContentEditorPresenter`）维护学习数据，数据以 `LearningItem` 形式按"科目 + 子类别"存在 JSON 词库文件中。但学习数据目前只在表格/卡片/复习等界面展示，缺少**游戏化、趣味化**的单词练习玩法。

本方案设计一款 **"单词消消乐"**：
- 纯静态网页（HTML + CSS + JS），无第三方框架；
- 数据不写死在前端，而是**从内容编辑器读取**后动态注入；
- 用 **WebView2** 在 WinForms 内展示该网页，实现游戏界面。

---

## 2. 现状分析

### 2.1 数据来源（"内容编辑"）
- 入口：`Forms/ContentEditorForm.cs`，逻辑在 `Presenters/ContentEditorPresenter.cs`。
- 数据模型：`Models/Learning/LearningItem.cs`
  - `MainContent`：主内容（英语取 `Word`，语文取 `Character/Idiom/Title/Phrase`）
  - `Meaning`：释义（`Meaning.Content`）
  - `Pronunciation`：音标（`Main` / `UkPhonetic` / `UsPhonetic`）
  - `Example`：例句
  - `WordFeatures`：词性、词形、搭配等
  - `ExtendedProperties`：扩展属性（如 `Synonyms`、`Antonyms`、`PartOfSpeech` 等模板字段）
- 读取服务：`Services/Learning/ContentLoaderService.cs`
  - `LoadItems(new LearningContext(userId, subject, subCategory))` → `List<LearningItem>`
  - 按子类别映射到词库文件，如 `SubCategoryType.EnglishWord` → `AppData/data/英语单词.json`
- 字段模板：`AppData/config/SubjectTemplates.json`
  - 英语单词模板字段示例：`Word / Phonetic / Meaning / Example / Synonyms / Antonyms / PartOfSpeech / WordForms / Collocations / Phrases / UkPhonetic / UsPhonetic ...`

### 2.2 展示方式（WebView2）
- 已有先例：`Forms/UserControls/KnowledgeGraphView.cs`
  - WebView2 加载本地静态 HTML：`CoreWebView2.Navigate("file:///资源目录/kg-visualization.html")`
  - 通过 `CoreWebView2.WebMessageReceived` 实现 C# ⇄ JS 双向通信。
- 独立浏览器窗体：`Forms/WebView2BrowserForm.cs`（多标签，可 `Navigate(url)`）。

> 结论：**数据源、数据读取服务、WebView2 展示机制三者都已具备**，本方案只需在此基础上新增"游戏网页 + 数据桥接 + 游戏宿主窗体"。

## 3. 游戏玩法设计

### 3.1 玩法定位（推荐：配对消除）
在一张卡片盘面上，混排**单词卡片**与**释义卡片**（也可能含音标/例句提示）。玩家点击一张单词卡片，再点击与之对应的释义卡片，若正确则两张卡片"消除"（动画消失）；错误则抖动并提示。所有配对消除后本局通关。

设计要点：
- 每局从当前词库中抽取 N 个单词（如 8~12 个），生成 `N` 张单词卡 + `N` 张释义卡，共 `2N` 张，随机打乱。
- 消除时触发"消消乐"风格的粒子/连击特效，消除数量越多连击分越高。
- 可选限制：计时、步数、错误次数上限，用于衡量熟练度。

### 3.2 备选玩法（Match-3 消除，作为二期扩展）
类似传统"消消乐"：盘面为格子，每个格子显示一个单词或释义；通过交换相邻格子，使 3 个以上**含义相同的单词/释义**连成一线而消除。该玩法棋盘算法较复杂，建议作为后续可选扩展，不在首版实现。

> 首版建议采用 3.1 配对消除，玩法简单、教育价值高、实现成本低。

### 3.3 游戏规则与反馈
- **正确配对**：两张卡片高亮 → 播放音效/粒子 → 消失 → 得分 + 连击。
- **错误配对**：两张卡片抖动、变红 → 1 秒后复原 →（可选）扣除生命。
- **通关**：所有卡片消除 → 结算页（得分、用时、正确率、连击最高值）。
- **重复挑战**：可换一组单词重新开局，或继续挑战下一组。
- 支持发音：点击单词卡可调用 `speechSynthesis` 朗读（WebView2 内置），增强记忆。

## 4. 数据接入方案

核心问题：**如何把"内容编辑器"里的 `LearningItem` 数据送进前端网页。**

### 4.1 推荐：C# 序列化后经 WebMessage 注入
流程：
1. 用户在游戏宿主窗体选择"科目 + 子类别"（默认英语单词）。
2. C# 调用 `IContentLoaderService.LoadItems(context)` 读取 `List<LearningItem>`。
3. 将 `LearningItem` 映射为精简的游戏数据 DTO（只保留 `word`、`meaning`、`phonetic`、`example` 等），序列化为 JSON。
4. 页面 `NavigationCompleted` 后，用 `CoreWebView2.PostWebMessageAsJson(json)`（或 `ExecuteScriptAsync` 注入）把数据交给前端。
5. 前端 `window.chrome.webview.addEventListener('message', ...)` 接收并初始化棋盘。

优点：
- 前端为纯静态页面，不感知文件系统、不感知 C# 内部结构；
- 数据可动态刷新（换词库不需要改 HTML）；
- 与现有 `KnowledgeGraphView` 的通信模式一致，复用成熟经验。

### 4.2 数据映射（LearningItem → 游戏数据）
```
{
  "id": "<item.Id>",
  "word": "<MainContent>",
  "meaning": "<Meaning.Content>",
  "phonetic": "<Pronunciation.Main 或 UkPhonetic>",
  "example": "<Example.Content 可选>",
  "partOfSpeech": "<WordFeatures.PartOfSpeech 可选>"
}
```
- 过滤条件：`MainContent` 与 `Meaning` 均非空的条目才进入游戏（否则无法配对）。
- 词库不足时（少于游戏所需张数），游戏给出提示并允许降低张数。

### 4.3 宿主窗体
新增一个游戏窗体（如 `WordMatchGameForm`），内部放置一个 `WebView2`：
- 加载 `Resources/WordMatchGame/index.html`（静态网页资源随程序发布）。
- 提供"科目/子类别"选择与"开始游戏/换一组"按钮（可放在网页内，也可在窗体顶部 ToolStrip）。
- 复用 `KnowledgeGraphView.cs` 中 `WebView2` 初始化与通信的写法。

## 5. 前端页面设计（静态 HTML）

### 5.1 文件组织
建议放在 `LearningAssistant/Resources/WordMatchGame/`（随程序复制到输出目录）：
```
Resources/WordMatchGame/
  index.html     # 页面骨架 + 布局
  style.css      # 样式（卡片、盘面、粒子、明暗主题）
  game.js        # 游戏逻辑（配牌、点击、消除、计分、结算）
```
- 纯原生 JS，不引入任何框架/CDN（保证离线可用、无外部依赖）。
- 页面顶部可读 `window.chrome.webview` 是否存在，用于区分"WebView2 内嵌"与"浏览器直接打开（开发调试）"两种场景。

### 5.2 页面布局
- 顶部：标题、得分、连击、剩余错误次数、计时（可选）、"换一组/重新开始"按钮。
- 中部：卡片盘面（`grid` 布局，2 列或按卡片数自适应，卡片可翻转显示单词/释义）。
- 底部：提示条（"请点击一个单词，再点击它的释义"）。

### 5.3 视觉与交互
- 卡片：圆角、柔和阴影、悬停上浮；单词卡与释义卡用两种底色区分。
- 消除特效：`CSS` 过渡 + `Canvas`/DOM 粒子（可复用项目 `ConfettiControl` 的思路，但前端用 JS 实现）。
- 明暗主题：与项目 `ThemeManager` 的明暗模式对齐（通过 C# 注入 `data-theme` 或前端读取系统偏好）。
- 发音：`SpeechSynthesisUtterance` 朗读单词，语言设为 `en-US`。

## 8. 技术要点与风险

1. **文件路径**：`Navigate("file:///...")` 需要绝对路径，用 `AppDomain.CurrentDomain.BaseDirectory` 拼接资源目录。
2. **中文 JSON**：`PostWebMessageAsJson` 需确保编码为 UTF-8，避免中文释义乱码。
3. **数据为空/不足**：词库为空或少于所需张数时，前端需给出友好提示，C# 侧也做兜底。
4. **发音可用性**：WebView2/设备若无可用的 `speechSynthesis` 语音，需静默降级（不播放即可，不影响游戏）。
5. **主题一致**：游戏页明暗模式尽量与 WinForms 主题联动，避免突兀。
6. **前端调试**：开发时可直接用浏览器打开 `index.html`，通过 `?mock=1` 或内置示例数据联调，不依赖 WebView2。

## 11. 优化建议（已采纳进方案）

以下优化点已并入上文各章节的核心设计，作为实现时的既定要求：

1. **复用现有服务**：直接使用 `ContentLoaderService.LoadItems`（自带缓存），不重复造词库读取逻辑。
2. **DTO 映射下沉为服务**：`LearningItem → 游戏数据` 的映射与过滤（`MainContent`/`Meaning` 非空）封装进 `WordMatchGameService`，便于单测，前端只拿"干净"数据。
3. **选词策略**：支持按"新词 / 复习词 / 错题"筛选（基于 `LearningItem.Status`、`ReviewCount`），让游戏参与复习闭环。
4. **成绩回写**：见第 10 节决策点 4，打通"游戏 ↔ 复习体系"闭环。
5. **难度分级**：按"单词数量 + 是否显示音标/例句提示"分难度，适配不同年龄段。
6. **统一 HTML 资源加载**：抽 `WebView2HtmlLoader`（`file:///` 路径拼接 + 存在性校验），`KnowledgeGraphView` 与游戏窗体共用，避免散落。
7. **通信协议化**：JS ⇄ C# 用 `{type, payload}` 消息结构，便于扩展"换一组 / 上报成绩"等。
8. **安全**：注入数据 JSON 序列化转义，防止前端执行注入内容；`file:///` 路径做存在性校验。
9. **空数据兜底**：前端 + C# 双重提示，并提供"降低张数继续"。
10. **前端独立调试**：`index.html?mock=1` 用内置示例数据，浏览器直接开发，不依赖 WebView2；资源版本化避免 WebView2 缓存旧 HTML。
11. **性能与体验**：单局卡片数上限（约 20 张），消除动画用 CSS transform；配对音效 + 单词朗读（`speechSynthesis`），无语音设备自动降级。
