# 多格式文档（Word / PPT）支持最终方案

| 项 | 内容 |
|---|---|
| 状态 | 评审稿（待确认） |
| 日期 | 2026-11-04 |
| 范围 | PDF 阅读模块新增 `.doc` / `.docx` / `.ppt` / `.pptx` 支持 |

---

## 1. 结论摘要

1. **方案选型**：Office 文档先转换为 PDF，再走现有 PDF 阅读全链路。高亮、标注、AI、TTS、划词翻译、搜索、自动框选、阅读打卡全部无需重写。
2. **改动量**：新增约 400–700 行、修改约 200–400 行，涉及约 8 个文件；不重构阅读器、不引入第二套渲染引擎。
3. **工期**：P0 4–6 人日可交付；P1 3–4 人日补齐目录/打卡/降级；P2 4–6 人日覆盖旧格式与体验优化。
4. **风险控制核心**：文档身份始终是“源文件路径”，转换产物只作为渲染输入；缓存按源路径隔离，绝不与学习数据绑定。
5. **明确不做**：`IDocumentPageSource` 双实现抽象、原生 docx/pptx 渲染、WebView2 内嵌 Office Online、图片模式中转。

---

## 2. 背景与目标

### 2.1 用户诉求

学习资料中除 PDF 外，存在大量 `.docx` 讲义与 `.pptx` 课件，希望能在同一阅读器中打开并继续使用标注、AI、朗读等学习功能。

### 2.2 支持等级定义

| 等级 | 能力 | 是否采用 |
|---|---|---|
| L1 外部打开 | 仅调用系统默认程序，无学习功能 | 作为兜底（转换失败时） |
| **L2 转换阅读** | 打开、翻页、文本层、高亮/标注、AI、TTS、翻译、搜索 | **本方案目标** |
| L3 原生渲染 | 自研 Office 排版引擎，支持动画/编辑 | 不采用 |

### 2.3 成功标准

- 中文 `.docx`（含表格、图片、分页）与 `.pptx`（含母版、备注）可正常打开与翻页。
- 划词、高亮、AI 问答、朗读、翻译在转换后的文档上可用。
- 关闭重开、清理渲染缓存后，标注与阅读记录不丢失。
- 转换失败时不阻塞阅读器，可降级为外部打开或文本提示。

## 5. 最终方案（v2）

### 5.1 总体架构

```
PdfReaderForm / PdfFileManager
        │  打开 source.docx
        ▼
DocumentOpenPipeline (唯一入口)
        │  1. DocumentFormats 判定格式
        │  2. 命中缓存？（源路径 hash + 源指纹 + 转换器版本）
        │  3. 未命中 → 后台转换 Office→PDF
        │  4. 返回 DocumentSource(sourcePath, renderPath)
        ▼
IPdfService.Load(renderPath)  ──►  PDFium 渲染 / 文本层
        │
        ▼
返回上层：文件身份 = sourcePath（标注、打卡、AI、索引、会话全部按源路径）
```

核心原则：

1. **一个入口**：格式判定与转换只发生在 `DocumentOpenPipeline`。
2. **两个路径**：`sourcePath` 用于数据身份；`renderPath` 只用于 PDFium 读取。
3. **缓存可丢，数据不丢**：缓存删除不影响任何学习数据。

### 5.3 文档身份映射（最关键）

| 数据 | 现有键 | 方案后的键 | 说明 |
|---|---|---|---|
| 标注 / 高亮 / 书签 | 文件路径 | **源路径** | 不随转换产物变化 |
| 阅读时长 / 打卡 | `DocPath` | **源路径** | `PdfReadingTimeStore` 本身不限扩展名 |
| 文本索引缓存 | 路径 hash + 指纹 | **源路径 hash + 源文件指纹** | 读取时用 `renderPath` |
| AI 缓存 / 翻译缓存 | 文档指纹 | **源文件指纹** | 重转不失效 |
| 渲染缓存 | `_currentFilePath + page + w + h` | **源路径 + 内容指纹 + page + w + h** | 防旧页图 |
| 缩略图 | 路径 + 大小 + 时间 | **源路径 + 大小 + 时间** | 可沿用现有实现 |
| 会话 / 最近文件 | 文件路径 | **源路径** | 恢复时按需转换 |

硬性规则：

- `FileLoadedEventArgs.FilePath` 必须传 `sourcePath`，否则 `PdfRenderer.Initialize`（`PdfPresenter.cs:1784`）的缓存键与标注身份会漂移到缓存目录。
- `PdfFileManager.CurrentFilePath` 不允许返回转换产物路径。
- 任何 UI 显示的文件名、页数、路径均从源文件读取。

### 5.4 缓存设计

目录：

```
%LocalAppData%/<App>/cache/doc_convert/
  <sourcePathHash>/
    manifest.json                  # 当前版本指针、历史版本、最近访问
    <sourceFingerprint>_<converter>.pdf
    <sourceFingerprint>_<converter>.meta.json
```

`manifest.json` 字段：

```json
{
  "schemaVersion": 1,
  "sourcePath": "D:\\资料\\课件.pptx",
  "current": "a1b2c3_lo7.6.4.pdf",
  "versions": [
    { "file": "a1b2c3_lo7.6.4.pdf", "pages": 24, "createdUtc": "...", "lastUsedUtc": "..." }
  ]
}
```

`.meta.json` 字段：

```json
{
  "schemaVersion": 1,
  "sourceSize": 102400,
  "sourceLastWriteUtc": "2026-11-04T02:11:22Z",
  "converter": "libreoffice",
  "converterVersion": "7.6.4",
  "pageCount": 24,
  "durationMs": 4321
}
```

缓存判定与失效：

| 场景 | 处理 |
|---|---|
| 源路径首次打开 | 转换并写 manifest |
| 源文件 size/mtime 未变、转换器版本未变 | 命中，直接返回 |
| 源文件变更 | 生成新版本文件，保留旧版本；`pageCount` 变化时提示“标注可能错位” |
| 转换器升级 | 生成新版本，不立即删除旧版本 |
| 用户“重新转换” | 强制生成新版本 |
| 清理缓存 | 跳过仍有活动会话引用的版本；其余按 LRU 淘汰 |
| 缓存删除 | 学习数据不受影响（数据键为源路径） |

缓存目录注册到 `CachePaths`（参考 `LearningAssistant.WinApp/Common/CachePaths.cs:50,236`），新增 `CacheType.DocumentConvert` 并纳入缓存清理界面。

### 5.5 转换器选型与探测链

优先级：

1. 用户设置中显式配置的转换器路径；
2. 已安装 Microsoft Office（COM：Word / PowerPoint）；
3. 已安装或随包分发的 LibreOffice（`soffice`）；
4. 均不可用 → 提示“未检测到文档转换组件”，提供“用默认程序打开”兜底。

| 转换器 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| Office COM | 版式最接近 Word/PPT，中文兼容好 | 需装 Office；STA 线程；弹窗/宏风险 | 首选（本机已装时） |
| LibreOffice | 免费、可随包或免安装 | 首次启动 2–5s；复杂版式/SmartArt 可能偏差；需中文字体 | 首选（未装 Office 时） |
| Aspose.Words/Slides | 无需 Office、结果稳定 | 商业授权成本 | 可选，不做默认 |

安全与稳定性要求：

- LibreOffice：独立 `-env:UserInstallation` 避免并发互斥；`--norestore --nolockcheck --headless`；设超时并强制结束子进程；串行 `SemaphoreSlim(1)`。
- Office COM：专用 STA 线程；`Visible=false`、`DisplayAlerts=0`、`ReadOnly=true`、`AutomationSecurity=msoAutomationSecurityForceDisable`；禁止更新链接/保存变更；超时回收。
- 转换在后台线程执行；`IPdfService.Load` 回到 UI 线程执行（PDFium 线程亲和）。
- 转换结果写入临时文件后原子替换，避免半成品被读取。

### 5.6 转换失败降级

| 失败原因 | 用户可见行为 |
|---|---|
| 未安装转换器 | 提示安装/配置路径，提供“用默认程序打开” |
| 文件损坏/加密 | 明确错误文案，不进入阅读器 |
| 转换超时 | 可取消，提示稍后重试 |
| 版式异常但转换成功 | 正常打开，记录告警日志 |

P1 可选：转换失败时降级为“文本只读视图”（`.docx/.pptx` 用 OpenXML 提取文本），不作为 P0 范围。

### 5.7 界面与交互

- 打开对话框、拖拽、目录对话框统一使用 `DocumentFormats.BuildDialogFilter()`。
- 打开 Office 文件时复用现有 `LoadingIndicator`，显示“正在准备文档（转换）…”，支持取消。
- 状态栏与标题显示源文件名，不显示缓存文件名。
- 页号语义：**以转换后的 PDF 页为准**，不承诺“Word 第 X 页”；页数变化时给出提示。
- 产品选项（P1）：PPT 导出是否包含备注页。

### 5.8 依赖注入改动

```csharp
// ServiceCollectionExtensions.AddPdfServices
services.AddScoped<IDocumentResolver, DocumentResolver>();
services.AddSingleton<IOfficePdfConverter>(sp => CompositeOfficePdfConverter.Create(sp));

// 文本索引：在 DI 层注入解析器，AI/翻译/框选/阅读器四个调用方零改动
services.AddScoped<IPdfDocumentTextIndex>(sp => new PdfDocumentTextIndex(
    sp.GetRequiredService<IPdfService>(),
    sp.GetService<IPdfOcrService>(),
    _ => new PdfiumPdfService(NullLogger<PdfiumPdfService>.Instance),
    sp.GetRequiredService<IDocumentResolver>(),
    sp.GetService<ILogger<PdfDocumentTextIndex>>(),
    AppPaths.PdfTextIndexDir));
```

`PdfDocumentTextIndex.GetOrBuildAsync(documentPath, ...)` 内部：

1. `await _resolver.ResolveAsync(documentPath)` 得到 `renderPath`；
2. 用 `documentPath` 计算缓存键与指纹；
3. 用 `renderPath` 构造/加载 PDFium 实例。

这样 `PdfAiService`、`PdfAutoLayoutService`、`PdfTranslationGlossaryService`、`PdfReaderForm` 的调用签名不变。

## 7. 分阶段实施

### P0：可用（4–6 人日）

任务：

1. `DocumentFormats` + `DocumentSource` + `IDocumentResolver`。
2. LibreOffice 转换器 + Office COM 转换器 + 探测链。
3. 缓存目录、manifest、源指纹判定、旧版本保留。
4. `PdfFileManager.LoadFileAsync` 接入解析器，确保身份为源路径。
5. 文本索引 DI 收口。
6. 渲染缓存键加入内容指纹。
7. 打开对话框、拖拽、目录对话框文案放行。
8. 加载进度与取消。

验收：

- 中文 docx（表格/图片/分页）与 pptx（母版/备注）可打开、翻页。
- 划词、高亮、AI、朗读、翻译、搜索可用。
- 关闭重开标注仍在；删除转换缓存后重开标注仍在。
- 同一文件二次打开不重复转换，耗时 < 1s。
- 转换器缺失时给出明确提示，不崩溃。

### P1：可用性补齐（3–4 人日）

- 目录扫描与左侧目录树支持 Office 文件（类型图标，不批量转缩略图）。
- 当前文档按需生成缩略图。
- 最近文件、会话恢复、阅读打卡放行。
- 设置页：转换器路径、PPT 备注页选项。
- 转换失败降级与"用默认程序打开"。

验收：含 50 个 docx 的目录可浏览且不卡顿；打卡报表可包含 Office 文档。

### P2：完整（4–6 人日）

- `.doc` / `.ppt` 旧格式。
- 音频匹配放行、批量 OCR 导出。
- 文本先行双通道（转换等待期先提供 AI/搜索）。
- 安装包内置或按需下载转换组件。
- 完整回归与性能优化。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 转换器依赖体积（LibreOffice 约数百 MB） | 安装包变大 | 检测已装环境优先；可选按需下载；文档说明 |
| 首次转换慢（2–10s） | 打开体验差 | 进度 + 取消 + 缓存；P2 预转换 |
| 分页与 Word 不一致 | 用户预期落差 / 标注错位 | 页号以 PDF 为准；页数变化提示；保留旧版本 |
| 中文字体缺失 | 版式漂移 | 校验样本、提示安装字体、必要时随包字体 |
| Office COM 弹窗/宏/线程问题 | 卡死或安全风险 | STA 专用线程、禁用宏与更新链接、超时回收 |
| 缓存被清理导致重复转换 | 性能抖动 | manifest 记录最近访问；清理策略排除活跃版本 |
| 数据身份误用转换路径 | 标注/打卡丢失 | 硬性约定：`CurrentFilePath = sourcePath`；代码评审重点 |
| 旧格式转换失败率高 | 用户投诉 | P2 单独批次，失败降级外部打开 |

## 10. 关键决策记录

### D1：为什么用 PDF 中转，而不是图片或原生渲染

- 文本层是现有 8 个功能的输入，PDF 转换天然保留文本层与坐标。
- 图片模式无文本层（`PdfPresenter.cs:1429`），会迫使 AI/TTS/翻译/高亮全部降级。
- 原生渲染需要重写分页、字体度量、图文混排，工期不可控。

### D2：为什么数据身份必须是源路径

- 现有标注、打卡、缓存全部按路径落盘。
- 若使用转换产物路径，缓存清理或重转会导致数据“消失”或错位。
- 转换产物只是可重建的中间物，不能承载用户资产。

### D3：为什么缓存文件保留旧版本

- 转换器升级或源文件修改可能改变分页。
- 保留旧版本可避免正在阅读的会话被破坏，并给用户“标注可能错位”的缓冲。
- 清理按引用与 LRU 执行，成本可控。

### D4：为什么不做 `IDocumentPageSource` 抽象

- 当前只有 PDFium 一种渲染实现，抽象没有第二个实现方。
- 会扩大改动面并引入不必要的接口兼容成本。
- 待将来真正接入第二渲染引擎时再抽象。
