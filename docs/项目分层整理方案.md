## 一、背景与目标

### 1.1 现状问题

当前 `LearningAssistant` 解决方案只包含两个项目：

| 项目 | TFM | 作用 |
| --- | --- | --- |
| `LearningAssistant` | `net10.0-windows7.0` + `UseWindowsForms` | 主程序，承载全部业务、服务、数据、UI、资源 |
| `LearningAssistant.Tests` | `net10.0-windows7.0` | 单元测试 |

存在的核心问题：

1. **分层混乱**：服务层、视图控件、模型、Presenter、资源、启动入口全部混在同一项目里，依赖关系无强制约束。
2. **平台耦合扩散**：`AppPaths`（静态类，全写死 `AppDomain.CurrentDomain.BaseDirectory`）、`MessageBox.Show`、`ShowDialog`、`BeginInvoke`、NAudio、KokoroSharp、PdfiumViewer、ScottPlot.WinForms、`user32/gdi32` P/Invoke 等平台耦合点散落在 Services / Presenters / Managers 各层，未做接口隔离。
3. **历史遗留代码堆积**：[LearningAssistant.csproj](file:///e:/Github/LearnTool/LearningAssistant/LearningAssistant.csproj) 中存在 13 处 `<Compile Remove>` 排除的废弃文件（如 `SiliconFlowAIService.cs`、`BaiduPanFileManager.cs`、`LearningItemMigrationService.cs`、`UserComparisonForm.cs` 等），未清理。
4. **Views 契约耦合 System.Drawing**：[IPdfView.cs](file:///e:/Github/LearnTool/LearningAssistant/Views/IPdfView.cs) 等接口签名含 `Bitmap` / `Image` / `Rectangle`，跨平台时需重写契约。
5. **MAUI 扩展无地基**：未来若要新增 `net10.0-android` 目标，没有"公共类库"作为双端共享层，所有服务代码会被强行复制或重写。

### 1.2 整理目标

- **抽离公共类库**：把与 UI 无关、与平台无关的业务/数据/服务/契约抽到独立 Core 类库，目标 `net10.0`（跨平台）。
- **界面项目瘦身**：WinForms 项目只保留 Form / UserControl / 平台专属服务实现 / 启动入口。
- **平台耦合接口化**：在 Core 中定义抽象接口（`IAppPaths` / `IAudioPlayer` / `INotificationService` / `IResourceLoader` / `IUiThreadInvoker` / `IDialogService`），WinForms 端实现，未来 MAUI 端再写一份实现，业务代码零改动。
- **Views 契约去 System.Drawing**：契约参数改用跨平台抽象（如 `byte[]` / `Stream` / 自定义 `ImageData` record）。
- **清理历史遗留**：删除 csproj 中 `<Compile Remove>` 列出的物理文件（确认无用后）。
- **为 MAUI 预留**：本阶段不创建 MAUI 项目，但 Core 项目结构、TFM、依赖必须满足"加一个 `net10.0-android` 项目引用 Core 即可启动"的条件。

### 1.3 不做的事

- ❌ **不创建 MAUI Android 项目**：用户明确要求"先不要做"。
- ❌ **不重写 UI**：WinForms 现有 Form / UserControl 保留，只做项目归属调整与必要的接口适配。
- ❌ **不替换第三方库**：PdfiumViewer、NAudio、KokoroSharp、ScottPlot.WinForms 等继续用，仅通过接口隔离。
- ❌ **不删除业务逻辑**：遵循 project_memory 硬约束，KidWinApp 合并历史代码全部保留，不简化、不重构、不删除。

### 2.2 依赖关系

```
┌─────────────────────┐         ┌──────────────────────┐
│  WinForms 项目      │ ──────► │   Core 类库          │
│  (net10.0-windows)  │  引用   │   (net10.0)          │
└─────────────────────┘         └──────────────────────┘
            ▲                              ▲
            │ 实现                          │ 引用
            │                              │
┌─────────────────────┐         ┌──────────────────────┐
│  Tests 项目          │ ──────► │  （可独立测试 Core）  │
│  (net10.0-windows)  │  引用   │                      │
└─────────────────────┘         └──────────────────────┘
```

- **Core 不引用 WinForms**，不引用 `System.Windows.Forms`、`System.Drawing`、NAudio、KokoroSharp、PdfiumViewer、ScottPlot.WinForms。
- **WinForms 引用 Core**，实现 Core 中的抽象接口。
- **Core 的 TFM 是 `net10.0`**（不带 `-windows`），确保 MAUI Android 可直接引用。

private static byte[]? BitmapToPng(Bitmap? bmp)

#### 3.9.4 配置加密跨平台处理

`ConfigEncryptionHelper` 当前用 DPAPI（`ProtectedData.Protect`）保护敏感配置。DPAPI 是 Windows 专属，MAUI Android 不可用：

- **阶段 0~4（本方案）**：保持 DPAPI 实现不变，`ConfigEncryptionHelper` 整体迁入 Core，但内部 DPAPI 调用通过 `IConfigProtector` 抽象：

- **MAUI 阶段**：DPAPI 失败时按 project_memory 已有规则"TryDecrypt 回退到原值"，保证向后兼容

    string Protect(string plaintext);

}

// LearningAssistant.Core/Services/Persistence/ConfigEncryptionHelper.cs
// 改为依赖 IConfigProtector 注入，移除直接 DPAPI 调用
