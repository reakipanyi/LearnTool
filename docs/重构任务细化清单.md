## 三、每次改动的工作流程

### 标准化改动流程

```
1. 【限定】确定本次改动仅涉及哪些文件
   └─ 列出: 改动文件列表、不改文件列表

2. 【备份】创建改动前的快照
   └─ git stash 或 git commit -m "before refactor xxx"

3. 【改动】按精确步骤逐一执行
   └─ 每完成一个step，立即编译验证

4. 【验证】运行相关测试
   └─ 单元测试 + 手动测试关键功能

5. 【记录】记录改动结果
   └─ 更新文档，标记验收标准完成状态

6. 【回滚】如果失败，立即回滚
   └─ git stash pop 或 git reset --hard
```

## 六、减少返工的核心原则

### 1. 单一改动原则
```
一次只改一件事
├─ 不同时改多个服务
├─ 不同时改接口和实现
└─ 不同时改代码和配置
```

### 2. 保持兼容原则
```
先扩展，后收缩
├─ 新增方法优于修改方法
├─ 保留旧接口优于删除接口
└─ 代理模式优于直接替换
```

### 3. 即时验证原则
```
每改动一个文件，立即编译
├─ 不累积多个改动再编译
├─ 发现错误立即修复
└─ 不继续下一步直到当前步骤通过
```

### 4. 文档同步原则
```
改动代码同时更新文档
├─ 接口注释同步更新
├─ DI注册注释同步更新
└─ 改动日志同步记录
```

## 七、风险控制矩阵

| 改动类型 | 风险等级 | 前置条件 | 后置验证 |
|----------|----------|----------|----------|
| 新增接口方法 | 低 | 无 | 编译+单元测试 |
| 新增实现方法 | 低 | 接口已定义 | 编译+功能测试 |
| 删除服务类 | 中 | 确认无引用 | 全项目编译 |
| 替换依赖 | 中 | 新依赖已实现 | 功能测试 |
| 修改接口签名 | 高 | 所有调用方已准备 | 全量测试 |
| 删除接口 | 高 | 所有实现已迁移 | 全量测试 |

### 高风险改动处理流程

```
高风险改动必须:
1. 先创建Feature分支
2. 在分支上完成改动
3. 通过所有测试后合并
4. 保留回滚路径至少1周
```
