# 专注力训练游戏 设计方案

> 项目：LearningAssistant（WinForms + WebView2）
> 目标：新增一款 **"专注力训练营"（Focus Training Camp）** 游戏集合：包含「数字追踪」「颜色 Stroop 测试」「视觉搜索」「舒尔特方格」四种子模式，全方位锻炼注意力、反应力与抗干扰能力。
> 本文档只做方案设计，不涉及代码实现。

---

## 1. 背景与目标

现有游戏（消消乐/翻牌/连连看/打地鼠）均围绕「单词 ↔ 释义配对」的记忆复习场景，缺少一款**纯能力训练、不依赖词库**的玩法，用于：
- 学习间隙的「大脑热身 / 注意力复位」；
- 儿童用户的专注力专项训练；
- 不依赖学习数据，随时可玩、即开即练。

本方案设计 **"专注力训练营"**：
- 复用已验证的 WebView2 静态页技术路径 + `WebView2GameFormBase` 宿主基类；
- 四款子模式可切换，统一计分与结算；
- 纯静态网页（HTML + CSS + JS），无第三方框架，离线可用。

## 2. 玩法设计

### 2.1 主模式选择页
启动后先进入「训练营大厅」，四张卡片对应四款子模式，点击进入对应玩法；结算后可返回大厅切换。

| # | 子模式 | 图标 | 核心能力 |
|---|---|---|---|
| 1 | 舒尔特方格 | 🔢 | 视觉广度 + 空间定位 |
| 2 | 数字追踪 | 👀 | 选择性注意 + 动态追踪 |
| 3 | Stroop 颜色 | 🎨 | 抗干扰 + 反应抑制 |
| 4 | 视觉搜索 | 🔍 | 并行搜索 + 目标识别 |

---

### 2.2 子模式一：舒尔特方格（Schulte Grid）
**经典专注力训练，5×5 方格内随机排列 1–25，玩家按顺序依次点击。**

- **盘面**：5×5（25格），数字 1–25 随机打乱填入，字体大小一致，无任何颜色区分。
- **规则**：从 1 开始按升序点击，必须依次点击（跳点无效），点错无惩罚但不前进。
- **限时**：不限时，但以**完成时长**作为核心评价指标；默认挑战上限 90s。
- **难度**：
  - **简单**：3×3（1–9）；
  - **普通**：5×5（1–25）；
  - **困难**：6×6（1–36）。
- **反馈**：
  - 点对：当前格高亮绿 + 下一格目标在标题提示；
  - 点错：红闪抖动 + 提示"请点 X"。
- **评价参考**：
  - 5×5 优秀 < 30s，良好 30–45s，及格 45–60s，>60s 加油。

---

### 2.3 子模式二：数字追踪（Number Tracking）
**多个彩色数字球在盘面内匀速漂移，玩家需追踪指定编号并按顺序点击。**

- **盘面**：一个矩形区域内，N 个编号小球（直径约 40px）持续以随机速度/方向移动，碰壁反弹。
- **规则**：开局提示"追踪编号 1→2→3…→K"，玩家在移动中依次点击对应编号的球；每轮 60s。
- **难度**：
  - **简单**：球数=6，速度慢，追踪 1→3；
  - **普通**：球数=10，速度中等，追踪 1→5；
  - **困难**：球数=15，速度快，追踪 1→7。
- **反馈**：
  - 点对目标：球短暂放大 + 计分 + 下一目标提示；
  - 点错球：失误+1，不中断继续。
- **额外刺激（可选）**：点对后目标球变色（防止追踪混淆）。

---

### 2.4 子模式三：Stroop 颜色测试（Stroop Effect）
**经典认知心理学测试：屏幕显示一个表示颜色的汉字（如"红""蓝""绿"），字体颜色与词义可能不一致，玩家必须快速选择**「字体的实际颜色」**而非字义。**

- **题目形式**：中央显示 2–3 字号大的颜色词（红/橙/黄/绿/蓝/紫），字体颜色随机抽取（可能与词义不同）。
- **选项**：底部 4–6 个颜色按钮（纯色块），玩家点击与**字体显示颜色**匹配的按钮。
- **限时**：60s，答对越多得分越高。
- **难度**：
  - **简单**：色词一致（字体颜色=词义），4 色；
  - **普通**：色词不一致（必须抑制干扰），6 色；
  - **困难**：色词不一致 + 反向指令（让选"词义对应的颜色"而非字体颜色，随机切换指令）。
- **反馈**：
  - 正确：绿圈 + 得分 + 连击；
  - 错误：红闪 + 失误 + 连击清零。

---

### 2.5 子模式四：视觉搜索（Visual Search）
**在一堆干扰图形中快速找出指定目标图形，考验并行搜索能力。**

- **盘面**：M×N 格盘（如 6×6 = 36 格），每格一张图形（方向箭头 / 字母 / 几何形状）。
- **规则**：顶部提示目标图形（如"🔴"或"字母 Q"），盘面内只有一个匹配，玩家限时内尽可能多局地找出目标。
- **干扰策略**：
  - **特征搜索（易）**：目标与干扰在单一维度差异（如在一堆○中找△）；
  - **联合搜索（难）**：目标是两个维度组合（如在一堆红○和蓝△中找**红△**）。
- **限时**：每局 60s，找出一题换一题，答对越多分数越高。
- **难度**：
  - **简单**：特征搜索，4×4 盘；
  - **普通**：联合搜索，6×6 盘；
  - **困难**：联合搜索 + 旋转（图形可旋转），8×8 盘。
- **反馈**：点对→爆炸特效，点错→小扣分。

---

### 2.6 通用计分与结算（四款共用）
- **计分**：每款有基础分 + 时间/连击加成，详见各子模式。
- **星级**：按得分排名 ★★★ / ★★ / ★ / 加油。
- **结算页**：总得分、正确数、失误数、最高连击、用时、对应子模式的额外指标（如舒尔特=完成时长秒数、追踪=命中率）。
- **再来一局**（同模式同参数） / **回大厅**（切换子模式）。

## 3. 数据接入方案

### 3.1 与现有游戏的关键差异：**不依赖词库**
专注力训练是纯能力游戏，不需要 `WordMatchGameService` 的词库取词 / 成绩回写。但仍需：
- 继承 `WebView2GameFormBase`（WebView2 初始化、主题、虚拟主机映射等通用能力）；
- 顶部「科目 / 子类别」栏可隐藏或改为「难度选择下拉」。

### 3.2 BuildData 返回内容
`BuildData` 不再依赖 `LearningContext` 取词，改为返回**配置与元数据**：
```jsonc
{
  "modes": [/* 四款子模式的元信息：id、名称、图标、默认难度参数 */],
  "defaultDifficulty": "normal",
  "theme": "light|dark"
}
```
前端据此渲染大厅卡与难度选择。

### 3.3 成绩回写语义
- **不写入学习数据**（无词库 → 无词条 → 无错题本）；
- **可选写通用统计**：新增 `FocusTrainingService`（或复用 `StudyStatsManager`），记录每局的「子模式、难度、得分、用时、正确率」到独立统计，供仪表盘展示"今日专注力训练时长"。
- 首版可先**省略后端成绩持久化**，仅前端结算展示得分即可；后续若要加入成就系统再补。

### 3.4 宿主窗体
新增 `FocusTrainingGameForm`：
- 继承 `WebView2GameFormBase`；
- `FormTitle` → "🎯 专注力训练营"；
- `HtmlFileRelativePath` → `Resources/FocusTrainingGame/index.html`；
- 重写顶部栏：将科目/子类别下拉替换为**难度下拉**（简单/普通/困难）+ **模式跳转按钮**。

## 4. 前端页面设计（静态 HTML）

### 4.1 文件组织
```
Resources/FocusTrainingGame/
  index.html        # 页面骨架（大厅 + 四款子模式容器）
  style.css         # 大厅、四款模式样式、动效、明暗主题
  game.js           # 主入口：模式路由、通用计分结算、通信
  modes/
    schulte.js      # 舒尔特方格：生成、点击判定、计时
    tracking.js     # 数字追踪：球物理移动、碰撞、追踪判定
    stroop.js       # Stroop：色词生成、按钮判定
    search.js       # 视觉搜索：图形生成、干扰策略、目标匹配
```
- 纯原生 JS，`?mock=1` 内置配置可直接浏览器打开调试。

### 4.2 页面结构（单页切换四模式）
- **大厅层（`.lobby`）**：四张模式卡片 + 顶部难度条；
- **游戏层（`.game-area`）**：根据当前模式 id 挂载对应子容器（舒尔特网格 / 追踪画布 / Stroop 题面 / 搜索格盘）；
- **结算层（`.result-overlay`）**：通用结算弹窗，得分/指标/星级/按钮。
- 顶部 HUD：返回大厅按钮、得分、计时、连击、当前目标提示。

### 4.3 动效与性能
- **舒尔特**：点击反馈用 CSS 类切换，避免重排；
- **追踪**：用 `requestAnimationFrame` 更新球位置，球用 `transform: translate(x,y)` 纯 GPU 合成；
- **Stroop**：题面淡出淡入，用 `opacity` 过渡；
- **视觉搜索**：格盘用 CSS `grid`，图形用内联 SVG 或 CSS 绘制（不依赖图片）。

### 4.4 共享前端公共件
- 继续沿用/接入 `Resources/Shared/*`（bridge、toast、theme、粒子、`{type,payload}` 协议）。

## 8. 技术要点与风险

1. **数字追踪性能**：15+ 球 `requestAnimationFrame` 每帧更新，用 `transform` 不触发 layout；避免每帧 `querySelectorAll`，缓存 DOM 引用。
2. **Stroop 题目生成**：保证"色词不一致"概率（普通难度不一致率 ≥ 70%），避免玩家钻空子直接点词义。
3. **舒尔特方格难度**：6×6 共 36 格字号要缩小，移动端/低分辨率注意可点击区域（Touch 友好，最小点击区 36px）。
4. **视觉搜索图形**：图形用纯 CSS / 内联 SVG 绘制，避免外部图片依赖；联合搜索要保证目标唯一、干扰维度可控。
5. **模式间切换**：单页路由要彻底清理上一模式的 timer / rAF / 事件监听，避免内存泄漏与"后台继续跑"。
6. **动画 fill 覆盖（老坑）**：四款子模式的正确/错误动画注意 `animation-fill-mode` 不覆盖终态类。
7. **中文 JSON 编码**：UTF-8。
8. **无词库依赖的 BuildData**：`BuildData` 在无 `LearningItem` 时仍返回有效配置（不返回 null），确保即开即用。
9. **主题一致**：`body[data-theme]` 联动。
10. **`?mock=1`**：内置模式配置 + mock init，浏览器直开即可调试。

## 11. 已采纳优化

### 专注力训练专有
1. **多模式即开即练**：大厅卡片切换，四款子模式共用同一 HUD / 结算 / 通信协议，降低维护成本。
2. **难度 = 统一三档**：四款子模式都抽象为简单/普通/困难三档，顶部一个下拉全局生效，不各自造难度轮子。
3. **舒尔特跳点无效不惩罚**：只让按顺序点，跳点只提示不扣分——儿童友好，避免挫败中断训练。
4. **Stroop 反向指令（困难档）**：随机让玩家选"字体颜色"或"词义颜色"，进一步训练认知灵活性（而不仅仅是背熟"只按颜色点"）。
5. **追踪模式目标变色**：点对后目标球变色，防止追踪视觉混淆（一堆球长得一样容易跟丢）。
6. **视觉搜索"只答对加分"**：答错只闪烁不扣分，鼓励快速扫视而不是怕错犹豫。

### 与其他游戏共用
7. **抽前端公共件 `Resources/Shared`**：bridge/toast/esc/theme/粒子/`{type,payload}` 协议继续复用。
8. **通用成绩上报模板**：即使无词库 id，仍用 `{mode, difficulty, score, correct, miss, timeMs}` 统一结构上报，方便后续接入统计服务。
