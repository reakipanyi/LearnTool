# 单词拼写 设计方案

> 项目：LearningAssistant（WinForms + WebView2）
> 目标：在现有"单词消消乐""记忆翻牌"基础上，新增一款 **"单词拼写"（听写 / Spelling）** 游戏：给释义/发音，玩家**键入**对应单词，锻炼"释义→单词"的产出式记忆。
> 本文档只做方案设计，不涉及代码实现。

---

## 1. 背景与目标

"消消乐""翻牌""连连看"都是**点选/配对**的识别式玩法，玩家始终能看到选项。缺少一款**产出式（recall）**玩法：要求玩家**主动拼写出**单词。

本方案设计 **"单词拼写"**：
- 复用已验证的 WebView2 + 内容编辑器数据 + 成绩回写路径（`WebView2GameFormBase` + `WordMatchGameService`）；
- 玩法核心差异：**看释义/听发音 → 键盘键入单词**，考验拼写记忆；
- 纯静态网页（HTML + CSS + JS），自带虚拟键盘，兼容触屏与硬件键盘。

---

## 2. 玩法设计

### 2.1 核心规则（听写 / Spelling）
逐题进行，每显示一道题：
- **题干呈现**：释义（中文）+ 发音按钮（🔊 `speechSynthesis`）+ 难度提示（首字母等可选）。
- **作答**：玩家键入/点选虚拟键盘拼出英文单词。
- **判定**（两种模式，可切换）：
  - **逐字母提示模式**：键入即比对，答对字母进入下一字母，答错记一次错误；
  - **整词提交模式**：输入完整单词后回车/提交判定。
- **结果反馈**：正确 → 绿色高亮 + 发音 + 下一题；错误 → 用红色高亮错误字母 + 显示正确拼写 + 进入复习池。
- 全部题做完 → 结算。

### 2.2 题型与内容
- **题型（可选）**：
  1. **看释义拼单词**（默认）：显示释义 → 拼出单词；
  2. **听音拼单词**：播放发音 → 拼出单词（不显示释义）；
  3. **看单词拼释义**：显示单词 → 键入中文释义（适合反向训练，中文输入法）。
- 抽词：复用 `BuildItems(context, N, selection)`，默认 `WrongFirst`（错题优先）；答错词条下一轮再进入薄弱字池。
- 难度分级（可选）：
  - **简单**：给首字母 + 字母数提示，不记错误次数；
  - **普通**：仅给字母数，限制错误次数；
  - **困难**：无任何提示，限时。

### 2.3 计分与反馈
- 计分：每题基础分（难度系数）− 错误/提示扣分，答对加分。
- **连击**：连续答对加分。
- 反馈：
  - 正确：绿框 + 读音 + 连击 toast；
  - 错误：错误字母红色标记 → 短暂显示正确拼写 → 下一题；
  - 答错的题计入"本轮错题"，结算页统一列出，并可一键加入错题本复习。

### 2.4 通关与结算
- 结算页：得分、答对数/总题数、正确率、最高连击、用时、星级、错题列表。
- "再来一局"（同组重排）/ "换一组"（重新抽词，走 `restart`）。

## 3. 数据接入方案

### 3.1 复用现有服务
- **取词**：`WordMatchGameService.BuildItems(context, N, selection)`，返回 `List<WordMatchItemDto>`（含 `Id / Word / Meaning / Phonetic / Example`）。拼写题需要 `Word` 作为答案、`Meaning` 作题干。
- **成绩回写**：`WordMatchGameService.ApplyResults(userId, context, results)`，答错的进错题本。
- **宿主**：新增 `SpellingGameForm`，继承 `WebView2GameFormBase`。

### 3.2 成绩回写语义
- 每个抽中词条记为一条结果：该题整词拼写正确 → `Correct = true`；拼错 → `Correct = false`（进错题本）。
- 前端在**每题作答完结后**即可增量上报，或全部完成后一次性 `gameEnd` 上报（与消消乐一致，统一在结算时上报）。

### 3.3 宿主窗体
新增 `SpellingGameForm`，与记忆翻牌一致，仅：
- `FormTitle` → "✍️ 单词拼写"；
- `HtmlFileRelativePath` → `Resources/SpellingGame/index.html`；
- `BuildData` → `BuildItems(context, 10, WordSelection.WrongFirst)`。

## 4. 前端页面设计（静态 HTML）

### 4.1 文件组织
```
Resources/SpellingGame/
  index.html     # 页面骨架（题干卡片 + 输入区 + 虚拟键盘 + 进度）
  style.css      # 题干、字母格、行/列输入、反馈、主题
  game.js        # 出题、输入判定、计分、结算、通信
```
- 纯原生 JS，无外部依赖，离线可用；支持 `?mock=1`。

### 4.2 页面布局
- 顶部：标题、得分、连击、进度（第 x/总题）、计时。
- 中部：题目卡片（释义 + 🔊 发音按钮 + 提示），下方**作答区**。
- 作答区（两种形态）：
  - **字母格**：按单词长度显示 N 个空格，逐字母填入（适合拼写）；
  - **输入框**：整词输入 + 提交按钮（适合整词模式/中文）。
- 底部：**虚拟键盘**（A–Z + 退格 + 清空），触屏可用；硬件键盘实时联动。
- 底部策略提示条。

### 4.3 输入与判定
- 逐字母模式：点击/键入字母填入当前格，填满即自动判定；答对锁定绿色，答错红色并进入下一题（显示正确拼写）。
- 整词模式：Submit/回车判定，大小写不敏感（首字母大小写容错），去首尾空格。
- 中文模式（看单词拼释义）：调用 IME，用输入框形态，与中文输入法兼容。
- 明暗主题：`body[data-theme]` 联动。

### 4.4 音标/发音
- 发音按钮调用 `speechSynthesis`（WebView2 内置）；无语音设备静默降级。
- 听音题型默认自动播放（可选开关）。

## 8. 技术要点与风险

1. **输入形态多**：字母格 vs 整词 vs 中文需在 JS 里统一状态，用"题型"配置驱动渲染与判定。
2. **大小写/空格容错**：英文判定统一 lowercase，去首尾空格；中文题型走 IME 输入框。
3. **听音题**：依赖 `speechSynthesis`，音质/语种受系统限制，静默降级并允许手动重播。
4. **中文输入法焦点**：WebView2 中输入框需保持焦点，避免 IME 候选窗丢失。
5. **成绩回写去重**：按 id 上报一次，`Correct` 为整词判定结果。
6. **动画 fill 覆盖**：字母格正确/错误高亮避免被入场动画 fill 覆盖。
7. **中文 JSON 编码**：UTF-8 传输，避免释义/答错展示乱码。
8. **词库不足**：少于所需题数时提示并降低 N。
9. **主题一致**：`data-theme` 联动。

## 11. 已采纳优化

### 单词拼写专有
1. **错误即时闭环**：拼错的词在本轮**倒序末尾再次出现**，形成"错→再练→对"的当轮闭环，而非只进错题本等下一次。
2. **形近词干扰（可选）**：出错后展示若干**拼写相近**的形近词（如 receive/recieve），帮助玩家区分易混词。
3. **顺序自适应**：先用简单词建立信心，再上错题/难词；用"间隔时长 + 错误次数"动态排序，而非固定顺序。
4. **混合题型交替**：同一批词既"看释义拼单词"又"听音拼单词"，交替出现，避免机械记忆。
5. **部分分评分**：非严格二进制——仅"差一个字母"给部分分并提示"很接近"（如 `rec:ve` 高亮差异字母），减少挫败，仍按 `Correct=false` 回写错题本但要区分"接近"反馈。

### 三款共用
6. **抽前端公共件 `Resources/Shared`**：把消消乐/翻牌/拼写重复的 `bridge()/sendToHost/toast/esc()`、发音、粒子反馈、主题变量、`{type,payload}` 消息协议、camelCase 封装统一抽取共享，各游戏只写差异。**当前代码库收益最高的一步**。
7. **统一难度/配置入口**：基类定义共识结构（如 `{difficulty, limit, hintBudget}`）由 `init` 下发，各前端复用，避免各自造难度轮子。
8. **通用成绩上报模板**：统一"每词条一条结果 + `correct` 布尔 + 局内 key 判定"协议，本款整词判定则复用同一 DTO。
