# 舒尔特方格 设计方案

> 项目：LearningAssistant（WinForms + WebView2）
> 目标：在现有"单词消消乐 / 记忆翻牌 / 单词拼写"等词库驱动游戏之外，新增一款 **"舒尔特方格"（Schulte Grid）** 专注力训练游戏：按顺序点击随机打乱的数字方格，锻炼视觉广度、空间定位与注意力分配。
> 本文档只做方案设计，不涉及代码实现。

---

## 1. 背景与目标

现有游戏（消消乐 / 翻牌 / 连连看 / 打地鼠 / 拼写）均围绕「单词 ↔ 释义」的记忆复习场景，**强依赖词库数据**。但在学习间隙、低龄用户、无可用词条等场景下，缺少一款 **即开即练、不依赖词库** 的纯能力训练玩法。

本方案设计 **"舒尔特方格"**：
- 复用已验证的 WebView2 静态页技术路径 + `WebView2GameFormBase` 宿主基类；
- 纯前端生成数字盘面，**不读取任何学习数据**，无词库也可游玩；
- 经典 5×5 默认盘面，支持 3×3 / 5×5 / 6×6 / 7×7 多档难度切换；
- 纯静态网页（HTML + CSS + JS），无第三方框架，离线可用。

> 与 [专注力训练游戏设计方案.md](专注力训练游戏设计方案.md) 的关系：那份文档把舒尔特作为四款子模式之一放入"专注力训练营"集合。本文档把 **舒尔特方格** 抽出为独立游戏，便于单独开发、单独入口、单独迭代；后续若做训练营集合，可复用本方案的盘面与判定逻辑。

## 2. 玩法设计

### 2.1 核心规则（按序点击）
- **盘面**：N×N 方格（默认 5×5），盘内填入 1 ~ N² 的随机打乱整数，字体大小一致，无颜色区分。
- **作答**：玩家从 1 开始按升序依次点击数字格，必须顺序点击（跳点无效）。
- **点对**：当前格高亮绿色 → 下一目标在顶部 HUD 提示（"下一个：X"）。
- **点错**：当前格红闪抖动 → 提示"请点 X" → 不前进、不扣分（儿童友好）。
- **完成**：点击到最大数 → 本局结束 → 结算页。

### 2.2 难度分级
| 难度 | 盘面 | 数字范围 | 默认挑战上限 |
|---|---|---|---|
| 简单 | 3×3 | 1–9 | 30s |
| 普通 | 5×5 | 1–25 | 90s |
| 困难 | 6×6 | 1–36 | 120s |
| 专家 | 7×7 | 1–49 | 150s |

- 默认 **普通（5×5）**；
- 顶部"难度下拉"全局生效，切换难度立即重开一局；
- 难度下拉与基类的"科目/子类别下拉"位置对应（详见 §3.3）。

### 2.3 计时与计分
- **计时**：从首次点击"1"开始计时，到点击到最大数停止；以 **完成时长（秒）** 为核心评价指标。
- **计分**（参考值，便于排行榜/星级）：
  - 基础分 = `盘面格子数 × 100`（如 5×5 = 2500 分）；
  - 时间加成 = `max(0, 基准时长 - 实际时长) × 10`（基准时长 = 格子数 × 1.5s）；
  - 错误次数扣分 = `错误次数 × 50`；
  - 最终得分 = 基础分 + 时间加成 - 错误扣分（下限 0）。
- **错误**：点错（非当前目标）记一次错误，不中断、不扣时间。
- **星级**：
  - 5×5 参考：优秀 < 30s（★★★），良好 30–45s（★★），及格 45–60s（★），>60s 加油。

### 2.4 反馈与特效
- **点对**：格子背景变绿 + 缩放脉冲动画 + 已点数字变灰不可再点；
- **点错**：格子红闪抖动 + 顶部 toast "请点 X"；
- **完成**：盘面整体淡出 + 粒子彩屑（复用 `Resources/Shared/*` 粒子件）+ 结算页滑入；
- **下一目标提示**：顶部 HUD 大号数字显示"下一个：X"，方便低龄用户；
- **可选声效**：点对短"叮"音、点错短"嘟"音、完成欢快音（Web Audio API 合成，不依赖音频文件）。

### 2.5 结算
- 结算页展示：总得分、完成时长、错误次数、星级、本局盘面规格、个人最佳（首次无）；
- "再来一局"（同难度同规格） / "换难度"（回顶部下拉切换） / "关闭"。

## 3. 数据接入方案

### 3.1 与现有游戏的关键差异：**不依赖词库**
舒尔特方格是纯能力训练游戏，**不需要 `WordMatchGameService` / `ContentLoaderService` 取词**，也**不写入学习数据 / 错题本**。但仍需：
- 继承 `WebView2GameFormBase`（WebView2 初始化、主题联动、`{type,payload}` 协议、`?mock=1` 调试等通用能力）；
- 顶部"科目 / 子类别"下拉**重新定义语义**为"难度下拉"（详见 §3.3）；
- `BuildData` 返回**配置与元数据**，而非词条列表。

### 3.2 BuildData 返回内容
`BuildData` 不再依赖 `LearningContext` 取词，改为返回**配置与元数据**：

```jsonc
{
  "difficulty": "normal",       // 当前难度：easy/normal/hard/expert
  "gridSize": 5,                // 盘面规格 N（N×N）
  "numbers": [/* 1..N² 的随机打乱数组，由前端生成也可，这里仅作种子 */],
  "bestTimeMs": 0,              // 个人最佳时长（毫秒，首局为 0）
  "theme": "light"              // 主题：light/dark
}
```

> 盘面打乱由 **前端生成**（避免 C# 端重复实现随机算法，且 `?mock=1` 调试更方便）；`BuildData` 主要下发**难度配置 + 元数据**，前端据此渲染。

### 3.3 宿主窗体
新增 `SchulteGameForm`：
- 继承 `WebView2GameFormBase`；
- `FormTitle` → "🔢 舒尔特方格"；
- `HtmlFileRelativePath` → `Resources/SchulteGame/index.html`；
- 顶部栏**语义重定义**（不改基类，仅在子类层覆盖行为）：
  - "科目下拉" `_comboSubject` → 隐藏或改为只读"舒尔特方格"标题；
  - "子类别下拉" `_comboSubCategory` → 改为"难度下拉"（简单/普通/困难/专家）；
  - "行/列数控件" `_numRows / _numCols` → 隐藏（盘面规格由难度驱动）；
  - "开始游戏"按钮 → 保留，点击后按当前难度下发 `init`。
- 由于基类 `BuildData(LearningContext, string)` 签名要求传入 `LearningContext`，子类仍构造一个**占位 context**（如 `new LearningContext(userId, SubjectType.Math, SubCategoryType.None)`），但 `BuildData` 内部**不使用**该 context（不读词库）。

### 3.4 成绩回写语义
- **不写入学习数据**（无词库 → 无词条 → 无错题本）；
- **可选写通用统计**：首版可省略后端持久化，仅前端结算展示；后续若要加入"今日专注力训练时长"仪表盘，再补 `FocusTrainingStatsService`（记录 `{userId, mode, difficulty, timeMs, errors, score, timestamp}`）。
- 前端 `gameEnd` 上报统一结构：

```jsonc
{
  "type": "gameEnd",
  "mode": "schulte",
  "difficulty": "normal",
  "gridSize": 5,
  "timeMs": 32450,
  "errors": 2,
  "score": 2350,
  "star": 3
}
```

> 基类 `OnGameEnd` 解析此结构；首版 `OnGameEnd` 内部仅 `LogInformation`，不写库。

## 4. 前端页面设计（静态 HTML）

### 4.1 文件组织
```
Resources/SchulteGame/
  index.html     # 页面骨架（HUD + 盘面容器 + 结算层）
  style.css      # 盘面、格子、动效、明暗主题
  game.js        # 盘面生成、点击判定、计时、计分、结算、通信
```
- 纯原生 JS，无外部依赖，离线可用；支持 `?mock=1`（内置难度配置 + mock init，浏览器直开即可调试）。

### 4.2 页面布局
- **顶部 HUD**：返回 / 难度标签 / 当前目标（"下一个：X"）/ 用时 / 错误次数 / 得分。
- **中部盘面**：`display: grid` 布局，`grid-template-columns: repeat(N, 1fr)`，方格自适应居中；
- **底部策略条**：提示"按 1 → N 顺序点击"等说明；
- **结算层**：`.result-overlay` 模态覆盖，展示得分 / 时长 / 错误 / 星级 / 按钮。

### 4.3 盘面生成与判定
- **生成**：`[1..N²]` 数组 `sort(() => Math.random() - 0.5)` 打乱，填入 N×N 格；
- **判定**：维护 `currentTarget = 1`，点击格子若 `value === currentTarget` → 正确，`currentTarget++`；否则错误+1；
- **完成**：`currentTarget > N²` → 停表 → 计分 → 结算；
- **计时**：首次点 "1" 时启动 `performance.now()`，完成时计算差值；
- **重开**：清空盘面 → 重新生成 → 重置 `currentTarget / errors / 用时`。

### 4.4 动效与性能
- **格子点击反馈**：用 CSS 类切换（`.correct` / `.wrong`）+ `transform: scale()` 缩放，避免触发 layout；
- **红闪抖动**：`@keyframes shake` 短位移动画，0.4s 后自动移除类；
- **完成彩屑**：复用 `Resources/Shared/*` 粒子件（与消消乐/翻牌一致）；
- **大规格盘面（7×7）字号**：用 `clamp()` 自适应，保证最小可点击区域 ≥ 36px（触屏友好）；
- **动画 fill 防覆盖**：`animation-fill-mode: forwards` 仅用于入场，状态类（`.correct`）优先级高于动画终态，避免被覆盖。

### 4.5 共享前端公共件
- 继续沿用 / 接入 `Resources/Shared/*`：
  - `bridge()` / `sendToHost()` —— C# ⇄ JS 消息桥；
  - `toast(msg)` —— 顶部提示；
  - `esc()` —— ESC 关闭结算层；
  - 主题变量 —— `body[data-theme]` 联动；
  - 粒子反馈 —— 完成彩屑；
  - `{type, payload}` 消息协议 —— camelCase 字段，与基类一致。

## 8. 技术要点与风险

1. **大规格盘面字号**：6×6 / 7×7 共 36/49 格，字号需 `clamp()` 自适应，最小可点击区 ≥ 36px（触屏友好），低分辨率屏注意盘面整体居中与缩放。
2. **计时精度**：用 `performance.now()` 而非 `Date.now()`，避免系统时钟跳变；首次点击 "1" 启动，避免"读秒就开始"的紧张感。
3. **点击防抖**：触屏高频点击需 50ms 防抖，避免同一格被快速连点触发多次反馈动画。
4. **动画 fill 覆盖（老坑）**：`.correct` 状态类优先级需高于入场动画终态，避免绿底被入场动画覆盖回原色。
5. **模式切换清理**：重开 / 换难度时彻底清理上一局的 DOM 监听 / 计时器 / 粒子句柄，避免内存泄漏与"后台继续跑"。
6. **难度下拉与基类语义冲突**：基类 `_comboSubject/_comboSubCategory` 默认绑定词库子类别，本方案在子类层**重新填充下拉项**（简单/普通/困难/专家），不修改基类源码，避免影响其他游戏。
7. **占位 LearningContext**：`BuildData(LearningContext, string)` 签名要求传入 context，子类构造占位 context（如 `SubjectType.Math`），但内部不读词库；避免传 null 触发基类空引用。
8. **`NavigationCompleted` 补发**：若"开始游戏"在页面加载完成前被点击，`_pendingPayload` 由基类自动补发，子类无需额外处理。
9. **camelCase JSON**：`JsonSerializerOptions` 已在基类设为 `JsonNamingPolicy.CamelCase`，前端字段统一 camelCase。
10. **中文 JSON 编码**：UTF-8，结算页中文文案不乱码。
11. **`?mock=1` 调试**：内置难度配置 + mock init，浏览器直开即可调试，不依赖宿主。
12. **主题一致**：`body[data-theme]` 与宿主 `IThemeService` 联动，明暗主题切换不重开本局。

## 11. 已采纳优化

### 舒尔特专有
1. **跳点无效不惩罚**：只让按顺序点，跳点只提示不扣分——儿童友好，避免挫败中断训练。
2. **下一目标 HUD 提示**：顶部大号数字显示"下一个：X"，方便低龄用户与初学者，避免找数困难导致挫败。
3. **难度 = 统一四档**：简单/普通/困难/专家抽象为顶部一个下拉全局生效，不各自造难度轮子。
4. **计时起点延后**：从首次点击 "1" 开始计时，而非"读秒就开始"，给玩家扫视盘面的准备时间。
5. **点错不中断**：错误只记次数不中断、不扣时间，鼓励快速扫视而非怕错犹豫。
6. **大规格字号自适应**：6×6 / 7×7 用 `clamp()` 自适应字号，最小可点击区 ≥ 36px，触屏友好。
7. **个人最佳（可选）**：本地存储按 `(userId, difficulty)` 记录最佳时长，跨会话展示，形成"挑战自我"动力。

### 与其他游戏共用
8. **抽前端公共件 `Resources/Shared`**：bridge/toast/esc/theme/粒子/`{type,payload}` 协议继续复用。
9. **通用成绩上报模板**：即使无词库 id，仍用 `{mode, difficulty, timeMs, errors, score, star}` 统一结构上报，方便后续接入统计服务。
