# 优化改进方案 · 02 · 数据分析 · 统计底座模块

> **对应问题**：问题二 · 数据层 —— 统计数据多源口径不一、学习时长未记录、历史 JSON 数据未迁移、仓储层未注册。
> **对应优化项**：O-001（统一统计聚合服务 + 时长写入 + JSON 迁移），**P0 数据底座**。
> **关联问题编号**：W-005 / W-006 / W-011 / W-012（需求挖掘）；C-001 / C-006（部分）/ C-009（需求冲突）；B-009（边界场景）。
> **依赖**：本模块是所有统计/图表/报告/仪表盘模块的**数据上游**，优先级最高，先行实施。

---

## 一、现状分析

统计数据散落在多套来源，口径不一：

| 数据 | 存储位置 | 说明 |
| --- | --- | --- |
| 学习活动计数 | `LearningAnalyticsService`（JSON 每用户文件 `AppPaths.GetUserAnalyticsPath`，`UserAnalyticsData.DailyRecords/CategoryStats`） | 仅累加 `ItemsLearned/ItemsReviewed/CorrectCount/WrongCount`；`RecordActivity` **不写学习时长** |
| 经验/等级/连击 | `StudyStatsManager`（DB `StudyStats`，`XP=次数*100`） | 被 `GamificationService` 使用 |
| 今日学习/连续天数/学习进度 | `UserProfile`（DB） | 供首页 Dashboard 与状态栏 |
| 间隔重复 | DB `SpacedRepetitionItems` + `ReviewLogs` | 已有保留率、遗忘曲线、复习效率、热力图能力，数据较完整 |
| 错题 | DB `WrongAnswerItem`（`IWrongAnswerService`） | 独立 |
| 目标 | `ILearningGoalService` | 独立 |
| 番茄钟 | `PomodoroService`/`PomodoroSession` | 独立，含真实时长 |
| 笔记 / 收藏 | `INoteService` / `IFavoriteService` | 独立 |

**关键缺陷**：
1. `TimeSpentMinutes` 在整个代码库中**没有任何赋值点**（已全库检索确认），“学习时长”相关统计恒为 0，报告中的时长指标全部失真（W-005）。
2. JSON 与 DB 并存，同一指标多源、口径不一（W-006）。
3. 数据迁移服务 `Services/Migration/DataMigrationService.cs` 与 `Program.cs`（L71-L102）中的迁移调用**已被注释停用**（W-011）。
4. 仓储层（`IUserProfileRepository` 等）代码存在但未注册，依赖未解耦（W-012 / C-009）。

## 三、优化方案

### A1. 补齐数据写入（学习时长）

- 在 `LearningAnalyticsService.RecordActivity` 或统一聚合层增加**学习时长累计**：学习会话（`LearningSession`/`StudyEngine`）结束时按实际耗时写入当日 `TimeSpentMinutes`；同时合并番茄钟 `PomodoroSession` 的完成时长。
- 保留 `RecordActivity` 的调用点（`StudyEngine.cs` 内多处），但在其内部改为**同时写 DB**（新表或并入现有表），从根上消除 JSON 持久化。
- **时长口径（可配置）**：学习会话 + 番茄钟默认计入；PDF 阅读、游戏化学习、闪卡复习是否计入由设置开关控制（默认单列或按“学习行为”勾选计入），避免三个来源时长对不上。

### A2. 建立统一聚合服务 `LearningStatsAggregator`（新增）

- 单一入口，聚合以下服务数据：
  - `StudyStatsManager`（经验/等级/连击）
  - `ReviewLogs + SpacedRepetitionItems`（记忆）
  - `WrongAnswerItem`（错题）
  - `PomodoroService`（时长）
  - `ILearningGoalService`（目标）
  - `INoteService` / `IFavoriteService`（内容资产）
  - `UserProfile`（学习进度）
- 输出统一 DTO：`DailyOverview`、`WeeklyOverview`、`MonthlyOverview`、`TrendSeries`、`CategoryBreakdown`、`MemoryInsights`、`WrongAnswerSummary`、`GoalProgress`、`EfficiencyReport`。
- **聚合结果缓存**：复用现有 `CacheService`/`CacheManagerService` 缓存聚合结果，订阅 `EventBus` 学习事件（`LearningEvents`）作为失效触发器，避免每次打开统计中心全量查 DB（学习结束后自动失效刷新）。
- **渐进改造**：保留 `ILearningAnalyticsService` 现有接口签名，内部改由聚合/DB 提供数据，UI 分两批替换为聚合 DTO，避免一次性大重构（该接口被 `StudyEngine`、`LearningForm` 等多处引用）。

### A3. 历史数据迁移（JSON → DB）

- 启动迁移任务：把每用户 JSON `UserAnalyticsData`（`AppPaths.GetUserAnalyticsPath`）的 `DailyRecords`/`CategoryStats` 导入 DB；成功后打迁移标记并废弃 JSON 读写（参考 `StudyStatsManager.MigrateFromJsonToDb` 的标记模式）。
- **幂等与可重跑**：迁移以“迁移标记 + 幂等 upsert（按 用户+日期 主键）”实现，中断后可重跑不产生重复数据。
- 迁移在后台执行，不阻塞主窗体打开；失败降级为不迁移并打日志，不影响启动。

### A4. 统一统计口径

- 明确定义并文档化（作为聚合层唯一实现，供所有界面复用）：
  - 学习时长（分钟）= 学习会话 + 番茄钟完成时长；
  - 正确率 = Correct/(Correct+Wrong)；
  - 连击 = 有学习行为的连续天数；
  - 等级/经验以 `GamificationService` 为准。
- 口径在设置中提供开关（如是否计入 PDF/游戏时长），聚合层按配置计算。

### A5. DB 索引

- 迁移/上线时对高频查询字段补索引：`ReviewLogs(UserId, ReviewTime)`、`WrongAnswerItem(UserId, ...)`、`PomodoroSession(UserId, StartTime)` 等，避免数据量增长后统计中心变慢。

## 五、验收标准

1. 学习会话/番茄钟结束后，`TimeSpentMinutes` 有真实写入，时长口径可配置。
2. `LearningStatsAggregator` 输出全部 DTO，口径唯一（时长/正确率/连击/等级均与文档定义一致）。
3. 聚合结果有缓存 + EventBus 失效触发；打开统计中心强制刷新兜底。
4. 旧 JSON 数据可一次性幂等迁移进 DB，可重跑不重复；迁移不影响启动。
5. 高频查询字段已建索引。
6. 补充聚合口径测试（`LearningAssistant.Tests`：时长=会话+番茄、正确率、连击），作为后续重构护栏。

## 六、风险与注意事项

1. **数据迁移安全**：迁移前先备份 `AppData/`；采用“迁移标记 + 幂等 upsert”避免重复；迁移失败不影响启动（降级并打日志）。
2. **聚合服务回归风险**：涉及 `StudyEngine`、`GamificationService`、`MainPresenter` 多处调用，需跑 `LearningAssistant.Tests`（`LearningAnalyticsServiceTests`、`StudyEngineTests`、`UserSessionServiceTests` 等）。
3. **`RecordActivity` 高频调用**：若改为同步写 DB 注意性能，建议异步/批量落库，避免阻塞学习主流程。
4. **迁移与写入并发**：迁移期间避免与日常写入冲突（迁移先于日常写入或加锁），防止丢数据。
5. **缓存失效遗漏**：失效触发器需覆盖全部写入路径，并保留“打开统计中心强制刷新”兜底。
