# 注释保护式代码修改

修改代码时严格保护原有的注释内容，不得随意删除或覆盖注释代码和正常注释。

## 核心原则

### 1. 注释保护优先
- **绝对禁止**在未确认的情况下删除任何注释（包括被注释掉的代码和说明性注释）
- 修改代码时，保留相关的原始注释
- 即使注释看起来过时或错误，也不要直接删除，先标记为待确认

### 2. 何时可以修改注释
只有在以下情况才可以修改注释：
- **逻辑变更**：代码逻辑发生变化，原注释已与新逻辑不符
- **用户明确要求**：用户明确要求修改或删除特定注释
- **明显错误**：注释存在明显的事实错误且会造成误导

### 3. 注释修改原则
- **最小修改**：只修改与逻辑变更直接相关的注释部分
- **保留风格**：保持原有的注释风格和格式
- **更新而非删除**：优先更新注释内容，而不是直接删除
- **标记待确认**：不确定时保留原注释，可添加 `// TODO: 确认是否需要更新` 标记

## 具体操作规范

### 修改代码时
```
修改前先读取完整上下文（包括注释）
old_string 必须包含相关注释
new_string 中保留原有注释，仅更新与代码变更相关的部分
确保注释与代码的对应关系不变
```

### 重构代码时
- 移动代码块时，连同相关注释一起移动
- 拆分函数时，将对应注释拆分到新函数中
- 合并代码时，合并相关注释并去重

### 修复 bug 时
- 保留 bug 相关的历史注释（作为历史记录）
- 添加修复说明注释，而不是替换原注释
- 原注释错误时，保留并修正，不要删除

## 检查清单

每次代码修改完成后，检查：
- [ ] 原有注释是否完整保留
- [ ] 注释代码（被注释掉的代码）是否被误删
- [ ] 新增代码是否需要补充注释（但不强制）
- [ ] 修改的注释是否与逻辑变更对应
- [ ] 是否存在无理由删除注释的情况

## 反模式（禁止）

❌ 因为"注释过时"就直接删除
❌ 重写整个函数时清空所有注释
❌ 移动代码时丢失关联注释
❌ 用自己的注释风格替换原作者的注释
❌ 删除被注释掉的代码（除非用户明确要求）
