# Git 自动提交技能

## 作用
每次完成代码修改后，自动提交到 git，确保所有修改都有版本记录，防止因文件丢失、误删除等导致代码丢失。

## 触发条件
- 用户明确要求提交修改
- 每次完成一个功能点的修改后自动触发
- 用户手动调用 `/git-auto-commit`

## 执行流程

### 1. 检查变更状态
运行 `git status` 查看所有变更文件（包括未跟踪文件），了解当前工作区的变更状态。

### 2. 分析变更内容
运行 `git diff` 和 `git diff --cached` 查看详细变更内容，了解具体改了哪些代码。

运行 `git log --oneline -5` 查看最近的提交风格，保持提交说明风格一致。

### 3. 生成提交说明
分析所有变更，生成一个简短的提交说明（1-2句话），格式如下：

- 使用中文编写
- 说明变更的性质：新增功能 / 修复 Bug / 优化 UI / 重构代码 / 删除冗余代码
- 说明变更涉及的文件或模块
- 示例：
  - "新增聚光灯模式功能，优化PDF阅读器工具栏布局"
  - "修复夜间模式双页显示问题，优化翻译Tab页UI"
  - "重构PdfReaderNavigationManager，提取标注渲染逻辑"

### 4. 执行提交
使用 `git add` 逐个添加相关文件（不要使用 `git add -A` 或 `git add .` 批量添加）。

使用 `git commit -m "提交说明"` 提交变更。

执行 `git status` 确认提交成功，工作区干净。

## 安全规则
- 不要提交敏感文件（.env、credentials.json、配置文件中的密码等）
- 不要提交大型二进制文件（超过 10MB）
- 如果有未完成的修改，提示用户确认是否提交
- 如果有多个不相关的变更，分别提交（每个变更一个独立提交）
- 提交前检查是否有文件名变更（git mv），避免误删文件

## 执行提交的注意事项
- 提交说明使用 **中文** 编写
- 使用 `git commit -F <temp_file_path>` 方式提交，避免 PowerShell 中 heredoc 语法不兼容的问题
- 先将提交说明写入临时文件，提交后删除临时文件
- 这个技能只负责提交，不负责推送（push），避免意外推送
- 如果工作区没有变更，提示用户无需提交
- 如果变更中有新文件（untracked），确认用户是否要包含这些文件
